# 指示書の共通ルール(すべての tasks/NNN-xxx.md に適用)

指示書を読む前に、このファイルを読み、従うこと。

1. **決めたことを全部並べる**: 指示書に書いていないことを自分で決めたら(名前、値、アルゴリズム、ライブラリの使い方、テストの書き方、エラー時の扱いなど)、最後の報告に「**決めたこと**」という見出しを作り、1行ずつすべて並べる。何も決めていなければ「決めたこと: なし」と書く。
2. **推測で進めない**: 「〜のはず」「〜と思われる」で進めない。動作を確かめられないこと(Android の API の挙動、端末の仕様、指示書の解釈が2通り以上ありうることなど)に当たったら、そこで作業を止め、次の3点セットで報告して終わる。
   - **わからないこと**: 何が確かめられないか(1〜2文)
   - **考えられる選択肢**: 2〜3個。それぞれの長所と短所を1行で
   - **おすすめとその理由**: どれを選ぶべきか、なぜか
3. **許可外のコマンドを使わない**: ファイルを読む・調べるためのコマンド(`cat`、`sed -n`、`rg`、`ls`、`git diff` など)は使ってよい。それ以外(ビルド、テスト、`javap` など SDK やライブラリの中身を調べるもの、ファイルを書き換えるもの)は、指示書と codex-run の制約に書かれたものだけを、一字一句そのまま使う。必要なら実行せずに止めて質問する。ファイルの作成・変更は、コマンド(`echo >`、`sed -i` など)ではなく、編集の機能で行う。
4. **テストを弱めない**: 次のことはすべて禁止。
   - テストの期待値を、実装に合わせて変える
   - テストを消す、`@Ignore` を付ける、テストの実行対象から外す
   - 条件を緩める(`assertTrue(true)`、比較を `>=` に広げる、許容誤差を広げる、検証の行を消す、例外を握りつぶして通す など)
   - 指示書で指定されたテストの名前を変える、別の内容に差し替える
   仕様と食い違うと思ったら、直さずに、2 の3点セットで報告して止まる。
5. **確認していないことを「確認した」と書かない**: 報告には、実際に実行したコマンドと、その結果(テストの実行件数・失敗件数)を書く。
