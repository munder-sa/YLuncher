# GT8D IPv6補助

GT8DのWi-Fi用IPv6通信が、SIM側のIPv6経路へ流れ込む現象を回避するための専用アプリです。

パッケージ名: `local.gt8d.ipv6guard` / バージョン: 1.0

## 実機確認（2026年11月4日）

- 通常アプリから端末内のADBへ接続し、root実行できることを確認しました。
- ルールを意図的に削除すると、監視が7秒後に再適用しました。
- 端末を再起動し、アプリを手動で開かずに、起動通知から監視とルールが復旧しました。ワイヤレスデバッグを手動でONにする前のログで成功を確認しました。
- 再起動後も監視プロセスはrootで1つだけ動作していました。5555番のTCP待受はありませんでした。
- アプリ画面から監視を停止でき、現在のIPv6ルールは維持されることを確認しました。その後、自動適用を有効に戻しました。
- モバイルデータONのまま、Wi-FiのIPv4経由で `https://music.apple.com` へのHTTP接続を確認しました。Apple Musicアプリの実際の再生は別途確認してください。

APK SHA-256: `13A5046308C5A7DE140C42BB5DF73C8D13F8184D074EA266FD8D28A796BCBCEE`

## 動作

- 起動完了時にアプリが起動し、GT8D内のADBへ接続してrootで処理します。
- 端末内のUnixソケット `localabstract:gt8d-ipv6-guard` を使用します。このアプリ用のTCP待受は公開しません。
- `ip -6 rule add priority 32000 unreachable` を、該当ルールがない場合だけ実行します。
- rootの監視プロセスが10秒間隔で確認し、ルールが消えた場合に再適用します。同じ監視プロセスは重複起動しません。
- 15分間隔のAndroidジョブも登録し、監視プロセスの起動を再確認します。ジョブの実行時刻はAndroidの制御を受けます。
- IPv6全体を無効化する処理ではありません。通常のネットワーク選択でSIMを使う際のIPv6は残します。

## このGT8Dでの動作条件

Android 15（SDK 35）、ADBシェルがroot、ADB認証が無効、SELinuxがPermissiveの実機向けに作成しました。これらは作業前からの状態です。アプリはSELinux設定を変更しません。

このファームウェアでは通常のアプリから必要な起動用プロパティを設定できることを確認しました。起動時に `service.adb.listen_addrs` を端末内ソケットに設定し、必要な場合にADBサービスを再起動します。このプロパティは再起動で消えるため、次回もアプリが設定します。

Magiskの導入、system/vendorの書き換え、ブートイメージの変更、ADBのTCP待受の永続化は行っていません。ファームウェア更新などで権限やADBの仕様が変わると、この方法が動かなくなる可能性があります。

起動から適用まで、および消失から再適用までには時間差があります。起動直後から一切の経路漏れを許さない方式ではありません。

## 操作

初回起動で自動適用を有効にします。通常はその後、アプリを開く必要はありません。

- 「状態を更新」: 現在のルールと監視状態を表示します。
- 「今すぐ適用」: 設定と監視をすぐに確認します。
- 「自動適用を停止」: 次回起動時の適用と現在の監視を停止します。現在のIPv6ルールは残します。

アプリを強制停止すると、Androidの仕様上、手動で再度開くまで起動通知やジョブが止まる場合があります。

## 解除

アプリで「自動適用を停止」してからアンインストールします。監視はアンインストールでも10秒以内に停止します。アプリが作ったADB待受の設定は端末の再起動で消えます。

現在のIPv6ルールもすぐに解除したい場合は、監視停止後にroot ADBから以下を実行します。

```sh
ip -6 rule del priority 32000 unreachable
```

## 診断用の場所

- アプリのログ: `/data/user_de/0/local.gt8d.ipv6guard/files/events.log`
- 監視スクリプト: `/data/local/gt8d-ipv6-guard/guard.sh`
- 監視ログ: `/data/local/gt8d-ipv6-guard/guard.log`
- アプリ設定と有効フラグ: `/data/user_de/0/local.gt8d.ipv6guard/`

## ソースとビルド

ソースZIPにはJavaソース、マニフェスト、ローカル用ビルドスクリプトを含めています。外部ライブラリは使いません。

ビルドにはJDK、Android SDK Platform 35、Build Tools 36.0.0が必要です。`build.ps1` 内のSDK・JDK・出力先のパスを使用環境に合わせて変更してください。

配布するソースZIPに署名用秘密鍵は含めません。新しい鍵でビルドしたAPKは、インストール済みのものへ上書きできません。今回の作業環境には、更新用の元の署名鍵を保管しています。
