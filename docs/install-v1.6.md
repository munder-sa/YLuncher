# YLuncher v1.6 導入手順（GT8D）

## 設定画面の開き方

**アプリ一覧の上にある「設定」ボタンを押す。または、ドックの一番下の「アプリ一覧」（点が9つのアイコン）を長押しする。** 左パネルではドックが左端、右パネルとホームでは右端にある。分割中はパネル内で設定が開く。

この手順書は [v1.5 導入手順](install-v1.5.md) からの差分。接続・ビルド環境・初回の許可は、同書と [v1.0 導入手順](install-v1.0.md) を使う。2026-11-01 にリリース版を実機に入れ、既定のホームを YLuncher にした(§6)。

## 1. ビルドとインストール

作業中の変更を整理し、v1.5 手順 §1 の切り替えを次に置き換える。

```sh
git switch v1.6
```

ビルド・APK の出力先・接続方法は v1.5 と同じ。[v1.0 手順 §2・§3](install-v1.0.md) に従い、同じ署名鍵で本体と中継の debug APK を用意し、`install -r` で **本体→中継** の順に上書きする。初めて導入する場合は同書 §4 の許可も済ませる。

## 2. 名前と設定の引き継ぎ

Android のアプリ設定・ホームの選択・既定のブラウザ・通知へのアクセス・使用状況へのアクセス・他のアプリの上に表示で、本体の表示名が「GT8D Launcher」から **「YLuncher」** になる。中継と分割のパネル画面は **「YLuncher パネル」** になる。許可を確認するときはこの名前を探す。パッケージ名は本体 `com.gt8d.launcher`、中継 `com.gt8d.launcher.panel` のまま。

アイコンは暗い背景に白い画面の枠・仕切り・時計の線を描いた形（案 C）。中継は右側が白い面になる。常駐通知の名前は「YLuncher」、本文は「YLuncher 動作中」。

設定形式は v1.5 と同じ **版3**。`config/Model.kt` の `CONFIG_VERSION` と保存項目、`ConfigCodec.kt`・`ConfigRepository.kt` の移行処理で確認でき、v1.6 用の設定移行は無い。既存のセット・左右・比率・アプリなどを引き継ぐ。

## 3. v1.6 で変わった見え方

- 設定をアプリ一覧の「設定」から開ける。許可の帯は足りない内容を説明し、複数なら「許可が N 件足りません」と表示する。押すと「許可のチェック」に進める。
- セットのカード・切り替えの幕・起動画面の名前が「1  YouTube | パネル」のように番号つきになる。「＋ セットを追加」は一覧の最後の細い行になり、入っていないアプリのマスには「見つかりません」と出る。
- 画面の両端に白い取っ手が出る(ホームの操作の案内の文字は出さない)。
- ドックのセット追加は、分割した画面に「＋」を重ねたアイコンになる。押すと新しいセットの編集が開く。
- パネルのミニプレイヤーは、お気に入りが曲名の右、下の操作が「前・再生／一時停止・次」の1行になる。再生／一時停止は白い丸で表示する。
- 失敗は画面下に6秒残る通知帯で理由を知らせる。分割非対応やアプリなしなら「セットを編集」、分割や全画面起動の失敗なら「ホームへ」、ブラウザなしなら「ブラウザを選ぶ」から進める。時間がかかる場合やブラウザ起動失敗は説明だけを表示する。幕の間は待ち、取り消した場合は待っていた通知を出さない。重ね表示を許可していない場合は文字だけの短い通知になる。
- 幕に「開いています」が出て、0.8秒後に「ホームへ戻る」が出る。押すと取り消してホームへ戻る。取り消し後は5秒間、遅れて分割が出たらホームを前に戻す（使用状況の監視が使える場合、追加は最大2回）。次の操作を始めると見張りを止める。ホームへ戻るための幕には取り消しボタンは出ない。
- 安全モードのホームは「純正ランチャーを開く」「安全モードを解除」の2つのボタンを表示する。自動では純正に移らない。
- 再生中の曲が無く、最後に再生したアプリのセッションも無いときは、曲名のある一時停止中のセッションから最近更新された曲を表示する。再生情報が無ければ小さな待ち受け表示になり、ホームは「<アプリ名>を開く」、パネルは「開く」で起動できる。未インストールなら「アプリが見つかりません」と表示し、ボタンは出さない。

### Task 100〜109 で変わった見え方

- ホーム(分割していないとき): セットは高さ 104dp の横長カード(番号・左右のアイコン・左右の名前を 2 行)を 2 列。左の列の一番下に、アプリ一覧の「登録アプリ」を 96dp で並べた段があり、指で横にスクロールできる。押すと全画面で開く。
- ドック: アプリは 5 枠。上の 4 つは最近 7 日によく開いたアプリ(自動。設定「パネルとホーム」で「自分で選ぶ」に切り替え可)、5 つ目は設定アプリ(`com.suding.settings`)で固定。
- アプリ一覧: 登録したアプリだけ + 最後の「すべてのアプリ」。「編集」で押して登録・解除。最初の登録はパネル・ドック・セットのアプリ + 最近 30 日に使ったアプリから自動で作る。
- 純正ランチャーと分割アプリ(スプリットスクリーン)は、ドック・アプリ一覧・ホームの段に出ない。純正ランチャーへは設定の「純正ランチャーに戻す」で戻る。
- 設定は選択・主ボタンが白、ヘッダーは ← だけ。幕・起動画面も白とアイコンの表示。

## 4. 追加の動作確認・場面テスト

注意: ホームのミニプレイヤーの歌詞ボタンで歌詞表示をオンにすると、再生中の曲名・アーティスト・アルバム名・長さを LRCLIB(lrclib.net)に送って歌詞を探します。オフ(既定)の間は送りません。

設定の入口、許可の帯の行き先、番号つきの名前、取っ手、ミニプレイヤー、失敗の通知、幕の「ホームへ戻る」を画面で確認する。左右のパネルの作り方と場面テストの準備・結果の場所は [v1.5 手順 §3・§4](install-v1.5.md) と同じ。

幕の取り消しは画面のボタンで確認する。冷えた状態でセットを開き、0.8秒後の「ホームへ戻る」を押してホームに戻ること、取り消し後に次のセットを開けることを確認する。

場面テストにも、幕の取り消しの2場面がある（Task 096。debug 版の `DebugPanelReceiver` の `cancel` で取り消す）。`set_cancel_cold`（冷えた状態でセット1を開き 1.2 秒で取り消す → 分割の枠が無く、YLuncher のホームが前）と `set_cancel_thenOpen`（取り消しの 2 秒後にセット1を開き直す → 普通に分割で開く）。セット1が「左 YouTube・右 パネル」であることが前提。

```sh
bash scripts/device-scenarios.sh --only set_cancel_cold
bash scripts/device-scenarios.sh --only set_cancel_thenOpen
```

## 6. リリース版の導入(2026-11-01 に実施)

署名鍵のファイル(`keystore.properties`)が無いので、リリース版も debug と同じ署名鍵で作られ、debug 版の上に `install -r` で入る。版は `versionCode 16` / `versionName 1.6`(本体・中継とも)。

```sh
/home/munde/tools/gradle-run.sh :app:assembleRelease :panelhost:assembleRelease
adb.exe -s 192.168.137.248:5555 install -r <app/build/outputs/apk/release/app-release.apk の Windows パス>
adb.exe -s 192.168.137.248:5555 install -r <panelhost/build/outputs/apk/release/panelhost-release.apk の Windows パス>
adb.exe -s 192.168.137.248:5555 shell cmd notification allow_listener com.gt8d.launcher/com.gt8d.launcher.media.MediaListenerService
adb.exe -s 192.168.137.248:5555 shell pm grant com.gt8d.launcher android.permission.POST_NOTIFICATIONS
adb.exe -s 192.168.137.248:5555 shell cmd role add-role-holder android.app.role.HOME com.gt8d.launcher 0
```

確かめたこと: 通知へのアクセス・使用状況・重ねて表示・Bluetooth・通知の表示が許可済み、既定のホームと既定のブラウザが YLuncher、ホームボタンで YLuncher のホーム、帯のサービスと通知のサービスが動く、セット 1(YouTube | パネル)・セット 2(YouTube | Apple Music)の分割、ドックの設定ボタン。リリース版には場面テスト用の `DebugPanelReceiver` が無いので、場面テストは debug 版で行う。release 版は `run-as` で設定を読めない。導入前の設定の控えは `build/release-1.6/config-before-release.json`。

純正ランチャーをホームに戻すときは `cmd role add-role-holder android.app.role.HOME com.android.launcher3 0`。

## 7. v1.6.1(2026-11-01)

### 変わったこと
- ワイドのホームの下の段は、パネルのアイコン(パネルと同じもの・同じ並び)。最後に「＋」(パネルのアイコンの設定へ)。
- パネルのアイコンは最大 10 個。パネルの「アプリ」は最大 2 段のページ送り(横にスワイプ、下の点が今のページ)。1 ページに収まれば点は出ない。
- 分割がそろったのに 4 秒で時間切れになる不具合を修正。使用状況の記録の時計が端末の時計より約 0.5 秒遅れていたため、YLuncher 自身の画面の再開を目印にずれを補正する。分割の入口が何か動かした形跡のある時間切れは、分割の失敗(3 回で全部のセットが全画面になる)に数えない。
- 設定画面の読めなかった文字(「最大 N 個まで」など)を灰色にした。

### 導入
§6 と同じ手順で、release 版を本体 → 中継の順に `install -r`。入れた後に通知へのアクセスを許可し直す(§6 のコマンド)。版は 17 / 1.6.1。

分割が全部全画面になる状態(設定 →「許可のチェック」の分割の方式が「全画面」)になっていたら、同じ画面の「メーカー方式に戻す」で戻す。

### 自作のショートカットのアプリを分割で開く
起動するとすぐ別のアプリを開いて自分は閉じるアプリ(例: 自作の GPT Live)は、そのままでは分割の片側に置けない(すぐ消えるため、分割が成立しない)。アプリの `AndroidManifest.xml` の、ランチャーに出る Activity(`MAIN`/`LAUNCHER` を受けるもの)に次の `<meta-data>` を書くと、YLuncher はセットの分割で**行き先のアプリを置き、分割ができてから 1 回だけリンクを送る**。パネルから隣に開くときも同じ。全画面で開くとき(ホームの段など)は、今までどおりそのアプリ自身を開く。

```xml
<activity android:name=".LauncherActivity" android:exported="true" ...>
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
    <!-- 必須: 分割に実際に置くアプリ -->
    <meta-data android:name="com.gt8d.launcher.split.PACKAGE" android:value="com.openai.chatgpt" />
    <!-- 任意: 分割ができてから送る先(パッケージ/クラス) -->
    <meta-data android:name="com.gt8d.launcher.split.COMPONENT" android:value="com.openai.chatgpt/com.openai.chatgpt.MainActivity" />
    <!-- 任意: 送るリンク(ACTION_VIEW の data) -->
    <meta-data android:name="com.gt8d.launcher.split.URI" android:value="https://chat.com/?mode=voice" />
</activity>
```

- `PACKAGE` だけなら、行き先のアプリを分割に置くだけ(何も送らない)。
- 送る Intent は `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_SINGLE_TOP`(パネルから隣に開くときは `LAUNCH_ADJACENT | MULTIPLE_TASK` も)。`COMPONENT` が無ければ `PACKAGE` 宛て。
- `COMPONENT` は、分割の中にある行き先の**本体の画面**にする。中継の画面(ChatGPT なら `ChatGptDeeplinkActivity`)に送ると、行き先が冷えているとき分割の外に全画面で出ることがある(実機で確認)。
- 行き先のアプリが入っていない・`PACKAGE` が自分自身・左右の行き先が同じになる、のどれかなら、今までどおりそのアプリ自身で開く。
- セットの設定にはそのアプリ(例 GPT Live)のまま残り、カードや幕の名前・アイコンもそのアプリのもの。
- YLuncher の診断ログ(タグ `GT8D`)に `redirect target=… sent=true` が出れば送れている。

### GPT Live(自作)の更新
- ソースは `F:\ChatGPT-Live-GT8D-source`(WSL では `/mnt/f/ChatGPT-Live-GT8D-source`)。上の 3 行を入れた 1.2(versionCode 3)を導入済み。
- ビルド: PowerShell 7 で `pwsh -File F:\ChatGPT-Live-GT8D-source\build.ps1`(Windows PowerShell 5 では ZIP の型が見つからず失敗する)。出力は `F:\outputs\ChatGPT-Live-GT8D.apk`。
- 署名の鍵は 2026-11-01 に作り直した(ソースのフォルダの `launcher-signing.p12` と `launcher-signing.password`。消すと次のビルドで別の鍵になり、上書きできなくなる)。古い鍵の版からの更新では、一度アンインストールしてから入れた。

## 10. v1.6.4(2026-11-02)

### 変わったこと
- 121: PiP(小窓)で再生中のアプリを、分割の中のパネルから開くと、PiP を解いて「そのアプリ | パネル」の分割に組み直す(今までは別のタスクが分割に出て、PiP が黒いまま残った)。再生中なら組み直す間だけ一時停止し、開いたら再生を戻す。使うには、ユーザー補助の許可が要る(下の導入)。許可が無ければ今までどおり。
- 122: 本体を入れ直した直後(または本体が落ちた後)の最初のセットで、分割がすぐ解けていた。中継が、パネルが消えたときは閉じずにパネルを開き直す。

### 導入
§6 と同じ手順で、release 版を本体 → 中継の順に `install -r`。入れた後に通知へのアクセスを許可し直す(§6 のコマンド)。版は 20 / 1.6.4。

PiP の対応を使うときは、設定 → ユーザー補助 → 「YLuncher(PiP の判定)」を有効にする(YLuncher の設定の「許可のチェック」の「ユーザー補助(PiP の判定)」からも開ける)。adb なら、今の値に `:com.gt8d.launcher/com.gt8d.launcher.pip.PipWatcherService` を足して設定する:

```sh
adb shell settings get secure enabled_accessibility_services
adb shell settings put secure enabled_accessibility_services "<今の値>:com.gt8d.launcher/com.gt8d.launcher.pip.PipWatcherService"
```

入れ直す(`install -r`)と、YLuncher のユーザー補助が外れることがある(実機で確認)。通知へのアクセスと同じく、入れた後に有効にし直す。`settings put` は値を丸ごと置き換えるので、ほかのサービス(例: com.carsyso.main の AccessibilityHookerService)を消さないよう、必ず今の値に足す形で書く。

1.6.4 に上げた直後は、古い中継のタスクが残っていると、最初のセットが一度だけ失敗することがある(古い中継は 122 の仕組みを持たないため)。2 回目からは開く。

## 11. v1.6.5(2026-11-02)

### 変わったこと
- 123: 端末の Car アプリ(com.ds.backcar。CarPlay から車の元の画面に戻る)を分割中のパネルから押すと、YLuncher がそれを「パネルの反対側のアプリ」として覚えていた。Car は一瞬で閉じるため、その後のリンクで「Car | ブラウザ」の分割を作ろうとして Car を起動し、意図せず車の元の画面に戻るおそれがあった。Car のように一瞬で閉じるアプリは記録しない。GPT Live など分割の行き先を持つアプリの動きは変えない。

## 5. v1.5 に戻す

[v1.0 手順 §9「v1.5 から v1.0 に戻す」](install-v1.0.md#9-v15-から-v10-に戻す) と同じく、純正ホームを既定にしてから本体を停止し、同じ署名鍵の旧版 APK を本体→中継の順に `install -r -d` で上書きする。先に v1.5 の APK を用意する。

```sh
git switch v1.5
```

ビルドは §1 の参照先に従う。v1.6 と v1.5 は同じ設定形式（版3）なので、**v1.5 へ戻す場合は `config-v2-backup.json` を復元しない**。アプリをアンインストールせず上書きし、起動後にセットと許可を確認する。v1.0 まで戻す場合は版2の復元が必要なので、上記 v1.0 手順 §9 に従う。今回、版を戻す実機操作は確認していない。
