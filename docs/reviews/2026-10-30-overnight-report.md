## 3. 判断してほしいこと

### 3-1. 冷えた起動でリンクが全画面になる件(重要)
**何が起きるか**: E は冷えたパネルをいったん全画面で起動し、3秒後の再試行でもう一度 E を呼ぶ。その遷移がまだ終わらないうちに分割の成立(ready)が来て、ブラウザを開くので、パネルのタスクが分割から外れる。黒い画面にはならず、全画面のブラウザとして使える。

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **A(おすすめ)** 分割の右のブラウザを、別の画面(BrowserActivity)にせず、**パネルの画面の中に表示**する。「閉じる」でパネルの表示に戻る | タスクの遷移に左右されない。GT8D の分割の性質に依存しない | 仕様 §4.7・§5.2 の「パネルのタスクに重ねる」を変える。パネルの画面が大きくなる |
| B 分割の成立後、さらに一定時間(例: 1秒)待ってからブラウザを開く | 変更が小さい | 待ち時間は経験則で、車の実機で外れる恐れ。リンクを開くのが遅くなる |
| C いまのまま(冷えたときだけ全画面) | 何もしなくてよい | 1回目のリンクだけ挙動が違う |

### 3-2. Task 18(設定画面)の論点
codex と整理した。**4本に分ける(18a 共通基盤・遷移 → 18b セット編集 → 18c 日常の設定 → 18d 許可・復旧)**のがおすすめ。決めないと手戻りが大きい論点:

1. **安全モード(退避)から設定へどう入るか、解除後どこへ戻すか**: A(おすすめ)パネル(ランチャーの入口)に復旧用の導線を設け、解除後は通常のホームへ / B 退避中のホームに設定ボタンを置く / C 解除機能だけ作り、入口は adb などの外部起動に限る
2. **分割中に設定を開く場所**: A(おすすめ)パネルのタスクに重ねる(分割の遷移中は入口を無効) / B 常に全画面で開く。※ 3-1 で A を選ぶなら、設定も「パネルの中に表示」に揃えるのが自然
3. **保存の単位**: A(おすすめ)詳細画面で「保存」、戻るで破棄。分割ボタン経由のときだけ保存後に開く / B 変更ごとに保存
4. **並べ替え・削除の後の「今のセット」**: A 番号を保つ(並べ替え後は別のセットを指す) / B(おすすめ)ID で同じセットを追う。削除されたらホーム
5. **車の接続待ち・分割非対応の警告**: A(おすすめ)今回は無効表示・「未判定」の案内にして後の Task へ / B 今回、検知・判定の調査から実装
6. **アプリの選び方**: A(おすすめ)パッケージ単位(今の設定の形のまま) / B 起動画面(Activity)単位
7. 帯の幅・長押しの時間: A(おすすめ)少数の選択肢から選び、すぐ反映 / B 数値入力 / C 次回起動で反映(※手戻りは小さい)
