# YLuncher v1.6 UX 改善 設計書

- 日付: 2026-10-31
- ブランチ: `v1.6`(main = v1.5、タグ `v1.5`)
- 元: UX 改善点の洗い出し(https://claude.ai/artifact/5ZHvAZoqmpSKisHih3ex2N、`build/ux-review/index.html`)の 18 件。番号はその一覧の番号。
- 元の仕様: `docs/superpowers/specs/2026-10-28-gt8d-launcher-design.md`(r3.0)。本書はその差分。

## 1. ユーザーの判断(2026-10-31)
- 一覧の改善案は、次の2点を除いて推奨どおり進める。
  - **ドックに文字は付けない**(元の仕様「アイコンの名前は出さない」を維持)。#2 はアイコンの形だけ替える。
  - **流れる曲名(#12)は今のまま**(幅を超えるときだけ、3秒待って1周)。
- **緑(`Palette.Accent`)はやめ、白に統一する**(設定・幕・起動画面・帯の触ったときの色)。
- 進め方は3段階: A(小さく効果が大きい)→ B(操作の分かりやすさと回復)→ C(見た目の整理。モックで選んでから)。

## 2. 共通の決まり(変えない)
- タッチ領域 72dp(`Dims.MinTouch`)、本文 20sp(`Dims.BodyText`)、走行中も動作を変えない、幕の安全タイマー 4 秒。
- UI 文言は日本語。利用者に向けた通知・説明は**敬体**(「〜できませんでした」「〜してください」)、ボタンは短い動詞(「開く」「追加」「ホームへ」)。
- 呼び名: 正式は「**画面セット**」、短くは「**セット**」。パネルの縦のバーは「**ドック**」(「右端バー」はやめる)。

## 3. 段階 A(小さく効果が大きい)

### A1(#3)設定の入口を見えるところにも置く
- アプリ一覧の画面(`ui/apps/AppListScreen`)の上部の見出しの行に「⚙ 設定」ボタン(72dp、`Icons.Default.Settings` + 文字「設定」)。押すと今の長押しと同じく設定を開く(分割中はパネルの中で、そうでなければ SettingsActivity)。ドックの長押しは残す。

### A2(#4)「許可が必要」から足りない許可へ直接行く
- 帯(`PermissionBanner`)の文言を、足りないものに合わせて「再生情報の表示に許可が必要です」「画面の端の操作に許可が必要です」「アプリの切り替えの検知に許可が必要です」(複数なら「許可が2件足りません」)にする。
- 押すと設定の「許可のチェック」(`SettingsRoute.Permissions`)を開く(Android のアプリ情報には行かない)。

### A3(#11)「＋ セットを追加」を小さくする
- `HomeSetCards` の追加カードを、セットのカードの行から外し、一覧の最後に**高さ 72dp・全幅の行**として置く(白い点線の枠、文字「＋ セットを追加」)。行数・カードの高さの計算(`rows`・`cardHeight`)から追加を除く。ホーム・パネルのセット表示の両方。

### A4(#13)セットの呼び名をそろえる
- 幕・起動画面のセット名を、カードと同じ「**<番号>  <左の名前> | <右の名前>**」にする(今は「セット<番号>」)。番号は 1 から(ホームは「ホーム」のまま)。
- カードの名前の前にも番号を付ける(20sp・`Palette.Muted`)。
- 設定の「パネルとホーム」の説明の「右端バー」→「ドック」。

### A5(#1 の一部)帯に取っ手を出す
- 帯(`EdgeStripService`)の中央に、幅 4px・高さ 96px・角丸の白い取っ手を、**不透明度 0.25** で常に出す(触ったときは今の光り方を白で)。帯の幅・判定は変えない。
- ~~ホームの時計の下に、初回から 5 回だけ操作の案内を出す~~ → **やめる**(2026-10-31 ユーザーの判断: 説明の文字は要らない、シンプルに)。

## 4. 段階 B(操作の分かりやすさと回復)

### B1(#2)ドックの「分割」のアイコンを「セット追加」の形に
- `Dock` の分割ボタン(`dock_split`)のアイコンを、`SetIcon`(左右 6:4 の四角)に小さな「＋」を重ねた独自の `ImageVector`(`SetAddIcon`)にする。`contentDescription = "セットを追加"`。文字は付けない。動作は今のまま(新しいセットの編集)。

### B2(#5)失敗の理由と次の操作を残す
- 今の短い通知(Toast「分割が使えなくなりました」「切り替えに失敗しました」)を、**画面の下に 6 秒残る通知帯**(Snackbar 風、`Palette.Panel` の地・白文字・72dp のボタン)に替える。原因別の文言と操作:
  - 分割に対応していないアプリ: 「<アプリ名>は分割に対応していないため、全画面で開きました」+「セットを編集」
  - 分割の方式が使えない/起動に失敗: 「分割で開けませんでした。<アプリ名>を全画面で開きました」+「ホームへ」
  - アプリが入っていない: 「<アプリ名>が見つかりません」+「セットを編集」
  - 4 秒の安全タイマー: 「開くのに時間がかかっています」(操作なし)
- 通知帯はアプリの上の重ね表示(帯と同じ仕組み)で出し、ホーム・パネル・他のアプリのどこでも見える。押せる領域は 72dp。
- リンク: ブラウザが無い →「リンクを開けるブラウザがありません」+「ブラウザを選ぶ」(設定の「リンクの行き先」)。ブラウザの起動に失敗 →「ブラウザを起動できませんでした」。
- 未インストールのアプリを含むカードには、マスの中に「見つかりません」を 20sp・`Palette.Muted` で出す。

### B3(#6)幕に「何を開いているか」と「ホームへ」
- 幕(`CurtainContent`)に、セット名(A4 の形)の下に「開いています」を出し、0.8 秒を過ぎたら下に「ホームへ戻る」(72dp)を出す。押すと幕を外してホームへ(開く処理を取り消し、遅れて分割が出てもホームを前に戻す)。4 秒の上限は今のまま。

### B4(#7)安全モードから戻る
- 安全モードのときのホームの説明の下に「安全モードを解除」(72dp。今の `SafetyRecoveryScreen` の解除と同じ処理)を置く。

### B5(#8)待ち受けのミニプレイヤー
- 起動し直した直後でも、**一時停止中のメディアセッションがあれば、その曲を出す**(`MediaWatcher` の選び方: 再生中が無ければ、最後に再生していたもの → 無ければ一時停止中のセッションのうち最近更新されたもの)。
- セッションが1つも無いときは、今の大きなアイコンをやめ、上寄せの小さなカード: アプリのアイコン 72dp・名前・「再生情報はありません」(`Palette.Muted`)・「<アプリ名>を開く」(72dp のボタン)。ホーム・パネルとも。

### B6(#9)パネルのミニプレイヤーの操作の並びを固定
- `MediaCard` の ☆ を、ホームと同じく曲名・アーティスト名の右(72dp)へ移す。下の操作は「前・再生/一時停止・次」の3つで固定の1行(折り返さない)。再生/一時停止は白い丸の地に暗い図柄(ホームと同じ)で 72dp。

## 5. 段階 C(見た目の整理。モックで選んでから)
- C1(#10)パネルのセット表示の専用カード(横長・高さ 104dp 程度・間隔 8dp)。
- C2(#14)幕・起動画面のパネルの絵を `PanelIcon` に統一(左なら反転)。
- C3(#15)緑をやめて白に統一: `Palette.Accent` を使っている所(設定の主ボタン・選択、幕の進行線・パネルの図柄、起動画面、帯の触ったとき)を白系に。テーマの `primary` も白。セグメントの選択の見せ方(白い面か、暗い面＋白い輪郭か)はモックで選ぶ。
- C4(#16)角丸と余白の段: 外側 24dp・内側 12dp・画像 8dp、余白 8/16/24dp。ホームのミニプレイヤーの左右 40dp は維持するかモックで確かめる。
- C5(#17)シーク: つまみのドラッグだけで確定(バーの単発のタップでは動かさない)。「−10秒/＋10秒」は付けない(ボタンが増えるため。必要ならモックで)。
- C6(#18)設定画面の細部: セットの編集を保存せずに戻るときの確認(「保存」「破棄」「続ける」)、片側をパネルにして反対側が未選択になったときの説明、即時保存の画面に「変更は自動で保存されます」、← と × の重複の整理、セット一覧の ▲▼・削除の見せ方(モックで)。
- 段階 C は、モック(HTML → Windows の Chrome で画像)を作ってユーザーに選んでもらってから、計画に書き足す。

### 段階 C の決定(2026-11-01、モック `build/mock/stage-c/*.png` でユーザーが選んだ)
- **C3 選択の見せ方 = 案A「白い面」**: 選ばれた選択肢(チップ・セグメント)は白い面に暗い文字、主ボタン(保存など)は白い filled ボタンに暗い文字。テーマの `primary` も白。緑(`Palette.Accent`)はアプリから無くす。
- **C6 セット一覧 = 案B「⋮ メニュー」**: 各行は番号・左右のアプリのアイコン 48dp・名前・比率(Muted)、右に「⋮」(72dp)だけ。押すとメニュー「上へ」「下へ」「削除」(削除は Danger の文字、確認のダイアログあり。端の行では上へ/下へを無効)。一番下の「セットを追加」は outlined ボタン(+ のアイコン)。
- **C6 編集の画面**: 「左」「右」「比率」の見出しは `Palette.Muted`(今は背景に溶けて見えない)。アプリは押せる行(アイコン 48dp・名前・「変更」と ›、72dp)。比率は1行のセグメント。「左右を入れ替える」は tonal ボタン。注意書きは Muted で見える色に。片側をパネルにして反対側のアプリが未選択なら、アプリの行を白い輪郭で強調し「反対側のアプリを選んでください」(Muted)。保存せずに ← で戻ると「変更を保存しますか?」(本文「保存していない変更があります。」、ボタン「続ける」「破棄」(Danger)「保存」(白い filled))。
- **C6 そのほか**: 設定のヘッダーは ← だけ(× をやめる)。すぐに保存される画面(操作・起動時・パネルとホーム・リンクの行き先など)の上部に「変更は自動で保存されます」(Muted 20sp)。
- **C1 パネルのセット表示 = 横長カード**: 狭いパネルの「セット」表示のカードを、高さ 104dp・間隔 8dp・角丸 24dp・地 Background1 の横長に。左に左右のアプリのアイコン(各 48dp、4dp 空け。パネルの側は PanelIcon)、右に「<番号>  <名前>」(番号 Muted・名前 白 20sp、1行で省略)。今のセットは白い輪郭 3dp。最後に outlined の「セットを追加」(72dp、全幅。100 と同じ控えめな見た目)。ホーム(ワイド)のカードは今のまま。
- **C2 幕・起動画面**: パネルの側の絵を `PanelIcon`(96dp、左パネルなら反転)に。アプリの側は頭文字でなくアプリのアイコン。進行線・今の位置の点を白(ほかの点は白の 40%)。起動画面の緑も白(主ボタンは白い filled)。
- **C4 角丸・余白の段**: 外側の面 24dp・内側の部品 12dp・画像 8dp、余白 8/16/24dp。ホームのミニプレイヤーの左右 40dp は維持。
- **C5 シーク**: つまみのドラッグだけで確定(バーの単発のタップでは動かさない)。

## 6. テスト
- 各項目にユニットテスト(Robolectric)を付ける(文言・押したときの行き先・大きさ 72dp・状態の出し分け)。既存のテストは弱めない(文言・色の変更に由来する期待値だけ合わせる)。
- 実機: 場面テスト(`scripts/device-scenarios.sh --with-ylauncher-home`)を各段階の後に全部流す。通知帯(B2)・幕の「ホームへ戻る」(B3)・待ち受け(B5)は、スクリーンショットで司令塔が確かめ、ユーザーに見てもらう。

## 7. 範囲の外
- ドックの文字のラベル。流れる曲名の変更。運転中の動画・ブラウザの扱い(方針の話)。Wi-Fi マークを押したときの動作(B12)。
