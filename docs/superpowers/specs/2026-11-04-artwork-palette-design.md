# ジャケット背景の色差改善

2026-11-04。ユーザーは背景コードの改善を了承。これはv2.0歌詞視覚設計§3の「最頻1色・RGB上限56・同色相の2色」を置き換える設計であり、Apple歌詞取得/解析の仕様変更は含まない。

## 狙いと範囲

- 異なるアルバムの特徴的な色を見分けやすくする。面積だけで1色を決めず、彩度と第2/第3の色を使う。
- ホームとパネルは同じ抽出結果と描画を使う。静止背景のまま、既存の共有・キャンセル・曲変更時の更新・最大辺32pxのサンプリング・元画像の寿命を維持する。
- 背景によって主要文字のコントラスト4.5:1を割らない。白、Muted、白0.62(次行/単語下地)とフェード中を確認する。歌詞の色/透明度を変更して帳尻を合わせない。
- 設定項目、追加依存、ぼかし、常時アニメーション、通信は追加しない。

## 抽出と色変換

1. 入力画素のalpha<128、max-min<24、max<32、min>224の除外と、RGB上位4bit/4096箱のalpha重み付き平均は維持する。無効/無彩色のみは既存Panelへ戻す。
2. 各箱の平均RGBをHSVへ変換。候補の重みは有効画素のalpha総和の1%以上とする。全候補がこの条件に届かない場合は最多の箱を候補に戻す。小画像の単色も1候補になる。
3. 候補の得点は `sqrt(箱の重み/総和) * (0.2 + 0.8 * 彩度)`。降順、同点はRGB箱番号の昇順。1色目から選び、既選択の全色と色相の最短距離が35度以上ある候補を最大3色まで選ぶ。再現性を持ち、1画素の色ノイズを背景全体へ広げない。
4. 選択色は色相を維持し、彩度を0.55〜0.90、明度Vを `0.45 + 0.15 * 元V` にする。灰色をRGBへ加算する旧変換は使わない。HSV→RGBは最終8bitで四捨五入する。
5. 各色を同じ倍率でRGB各成分へ乗算して暗くし、色相/彩度を保つ。倍率0〜1を16回の二分探索で求める。採用条件は、丸め後の相対輝度≤0.045、白/Muted/白0.62を合成した文字とのコントラストがいずれも4.65以上。最終値も採用条件を確認し、丸め境界で外れれば倍率を下げる。実装の計算式とは独立した参照計算でテストする。
6. 3色なら選択順で開始/中央/終了へ使う。2色なら中央は開始/終了のsRGB平均。1色なら開始/中央/終了を適合色の1.0/0.8/0.6倍にする。2色以上の時は異なる色を同じ暗色へ潰さない。0.5刻みの3停止点を持つ静止線形グラデーションとする。
7. `ArtworkColors` は既存light/dark(開始/終了)を維持し、中央色 `accent` を追加する。既存2引数のテスト用値を扱うためaccentの既定はlight。描画は開始/中央/終了の順。`darkenArtworkColor` は1色の新変換を提供する。純粋な計算とBitmap処理の境界は維持する。
8. 全停止点間の8bit丸めを含む補間でコントラストを検証。上記条件で4.5未満が見つかった場合、閾値を下げず、配色全体をさらに暗くする修正を司令塔へ報告する。基準を満たさない色を描画しない。

## テスト仕様の移行(ユーザー承認済み)

現行 `tasks/RULES.md` は「テストの期待値を、実装に合わせて変える」を禁止している。今回、ユーザーが承認した見た目の改善に伴い、旧暗色仕様と新仕様が衝突する。実装後の値に合わせて期待値を作るのではなく、以下の仕様更新を先に固定してから実装/検証する。

ユーザーは同日「新仕様に沿ってテストを更新する（推奨）」と明示了承した。この例外は下表の旧色仕様の移行に限り、4.5基準や既存のライフサイクル/描画検証の緩和には使わない。

| 対象 | 旧仕様に依存する検証 | 新仕様で検証する内容 |
|---|---|---|
| ArtworkColorsTest | 赤の固定#381818/#1C0C0C、全成分56以下、最頻箱のみ | 主要色の色相保持/彩度≥0.55、明るい赤/青の最大成分>56、最大3色、明記した得点/ノイズ除外/色差/同点規則、全補間の主要文字比≥4.5 |
| ArtworkBackgroundTest | 旧赤のサンプル期待値 | 新色のサンプル期待値。画像サイズ/コピー回避/非破壊/再利用/中断/古い結果排除の条件は維持 |
| HomeMiniPlayerTest | 赤背景の成分≤56 | 新背景の色反映・コントラスト。角丸/パディング/寸法/切替/再抽出回数/連続描画なしは維持 |
| MediaCardTest | 赤背景の成分≤56 | 新背景の色反映・コントラスト、背景なし時のPanelは維持 |
| LyricsVisualStyleTest | 旧変換を用いた背景集合 | 新しい開始/中央/終了と全区間も検証。既存4.5閾値・alpha・時間・除外範囲は維持 |

既存テストの削除/Ignore/対象除外/許容誤差拡大は行わない。旧仕様依存テストは目的を保って新仕様へ更新し、ノイズ/複数色/強さ/全補間の検証を追加する。無関係なテストには触れない。試験入力は人工画像を使い、実歌詞や認証情報を持ち込まない。

## 検証とベータ

- 上表の5クラスだけを `:app:testDebugUnitTest --tests ...` で実行する。失敗を修正した場合のみ再実行。
- 差分とXMLを司令塔が照合後、両モジュールを2.3.0-beta2 / 42に更新しrelease APKを作る。署名/版を照合して既存実機へ更新し、Lemon/怪獣/WAVESの異なるアルバムで色差と文字を確認する。
- ホーム/パネル、画像なし、歌詞表示切替、曲送り、連続再抽出なしを確認し、見た目はユーザーにも確認してもらう。数値だけで見た目の合格を断定しない。
- Apple歌詞の実機採用は別の未完了項目として残る。今回のインストールでメモリ上のWebトークンは保持できない。

## 決めたこと

- 彩度を考慮した最大3色と静止3停止点グラデーションを採用する設計にする。
- 色相差35度、候補1%、得点/HSV/輝度/コントラストの数値は上記を初期値とし、計算と実機の結果を記録する。
- 既存の処理量上限/共有/画像の所有権と文字の4.5:1基準は維持する。
- テストの旧RGB上限を新仕様へ更新する件は、RULESの明示禁止との衝突を説明しユーザーが承認済み。新仕様に基づく期待値で検証し、失敗に合わせて基準を変えない。
