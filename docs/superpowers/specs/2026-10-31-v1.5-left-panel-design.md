# YLuncher v1.5 左パネル対応 設計書

- 日付: 2026-10-31
- ブランチ: `v1.5`(v1.0 = タグ `v1.0`、右パネルのみの構成)
- 元の仕様: `docs/superpowers/specs/2026-10-28-gt8d-launcher-design.md`(r2.2)。本書はその差分。

## 1. 目的と要件(ユーザーの判断)

1. 画面セットごとに、パネルを**左にも右にも**置ける(「パネル | アプリ」「アプリ | パネル」「アプリ | アプリ」)。パネルは片側だけ。
2. 左パネルのときは、パネルの中の**ドック(右端バー)も左端**に置く(パネルを左右反転)。全画面のホームは変えない。
3. 左パネルのとき、パネル(ドック・アイコン一覧・ミニプレイヤー等)から起動したアプリは**右側**に出る。
4. 左パネルの分割で、右のアプリからリンクを押したら「**ブラウザ | アプリ**」で開く(今の動きの左右反転)。
5. システムの**仕切りのダブルタップ**で左右を入れ替えたら、その並びを**画面セットに保存**する。

## 2. 実機での確認(2026-10-31 実験。コードは残していない)

| 実験 | 結果 |
|---|---|
| ① 温まった状態で E に `com.gt8d.launcher.panel|com.google.android.youtube`・`2:3` | 中継のタスクが左 0..768px(40%)、中に PanelActivity。YouTube が右 783..1920。比率は左:右の順でそのまま効く |
| ② ①の左パネルのアイコン一覧からマップを起動 | マップは右(反対側)に出て、左のパネルは残る。今の `NEW_TASK | LAUNCH_ADJACENT | MULTIPLE_TASK` のまま |
| ③ 冷えた状態(本体・中継を force-stop)で①。既定のホームが純正/YLuncher の両方 | どちらも成功。SystemUI の異常終了なし。YLuncher のホームのタスク(affinity `com.gt8d.launcher.home`)はホームの場所に残り、分割に混ざらない |
| ④a 左パネルのまま右を YouTube → マップ | 成功。中継のタスクはそのまま |
| ④b 左パネル → 「YouTube | 中継」(3:2) | 成功。中継のタスクが左から右へ移る |
| ⑤ 「YouTube | パネル」で仕切り(x=1152..1167)の中央をダブルタップ(adb で `input tap` 2回) | 左右が入れ替わる(`onDoubleTappedDivider splitSwitching`)。パネルは幅 753px を保って左へ。PanelActivity は**作り直されない**(描き直しのみ)。`[Layout] strip window=(0,36-753,1080) pad=(48,0)` が直後に出る = 窓の位置の変化をアプリが捉えている |

結論: E・中継アプリ・隣に開く起動は、そのまま左パネルに使える。直すのはアプリ内の「パネルは右」の決め打ち。

## 3. データと設定画面

### 3.1 セットの型(設定の版 2 → 3)
- `ScreenSet(id, left: Slot, right: Slot, ratio, appPairLabel)`。`left` を `Slot.App` から `Slot` に広げる。
- 制約: `left` と `right` の両方が `Slot.Panel` のセットは保存しない(検証で弾く)。
- 比率は今までどおり**左:右**。パネルを含むセットの比率は `SplitRatio.forPanel`(4:6 / 5:5 / 6:4)。判定を `allowedFor(right)` から「左右のどちらかがパネルか」に変える(`allowedFor(set)` など)。
- 移行: 版 2 の JSON の `left` は `{"pkg": "..."}`(型の印なし)。版 3 では `Slot` の多態の形で読む必要がある。`ConfigCodec` で、版 2 の `left` を `Slot.App` として読み替え、`version = 3` にして保存する。`ConfigRepository` の既存の移行の仕組みに合わせる。
- `Defaults`(既定のセット)は変えない(左 YouTube・右パネル・6:4)。

### 3.2 設定画面(画面セットの編集 `SetsScreen`・`SetsEdit`)
- 左・右それぞれに「アプリ / パネル」の切り替えを置く。片方をパネルにすると、もう片方はアプリに固定(パネルを選べない)。
- **⇄(左右を入れ替える)**ボタン: 左右の Slot を入れ替え、比率を反転(3:7↔7:3、4:6↔6:4、5:5 はそのまま)。§3.3 と同じ規則。
- 一覧の名前は実際の並び(例「パネル | YouTube」)。
- 編集データ(`SetsEdit`)も左右対称に持つ(左がパッケージ文字列固定をやめる)。保存の条件・比率の補正・新規の初期値を左右対称に。

### 3.3 ダブルタップの入れ替えの保存
- パネルの側(§4.4)が「左→右」または「右→左」に変わったとき、次の**すべて**を満たせば、今開いているセットの左右と比率を入れ替えて保存する:
  1. 今開いているセット(`SetRunner` の現在のセット)にパネルがある。
  2. パネルの新しい側が、そのセットのパネルの側と**逆**である。
  3. 反対側の前面のアプリ(記録の組のうちパネルでない方)が、そのセットのアプリと一致する。
  4. セットを開いている最中ではない(`AppGraph.runner.opening.value == null`、幕が出ていない)。
- 両方アプリのセットの入れ替えは、アプリから観測できないため保存しない(その場限り)。
- 保存したら `DiagLog.d("SetRunner", "swapSaved index=N ...")` を出す(場面テストで使う)。

## 4. 分割の起動と、パネルからのアプリ起動

### 4.1 セットを開く(`SetRunner`)
- パネルのある側に中継アプリ `com.gt8d.launcher.panel` を入れて `VendorBridge.openSplit(left, right, ratio)` に渡す(`VendorBridge` は変えない)。
- `Opening`・`lastOpenedPair` は実際の左右の順で持つ。
- 成立の判定 `waitBoth`: 「アプリ側の Resume(UsageEvents)」+「PanelActivity の合図(`panelResumedInSplit`)」で成立、を左右どちらのパネルでも使う。呼び直しの抑止(`retry skipped`)も左右どちらでも効かせる。

### 4.2 逃がし先
- パネルを含むセットで、分割が使えない・起動に失敗: **パネルの反対側のアプリ**を全画面で開く。
- パネルを含むセットで、そのアプリが入っていない: ホームへ。
- 両方アプリのセット: 今のまま(左のアプリを全画面、右が無ければ左だけ)。

### 4.3 パネルからアプリを開く
- 変更しない(実験②)。

### 4.4 パネルが自分の側を知る
- `PanelActivity` が自分の窓の画面上の位置から `PanelSide { Left, Right, Full }` を決め、`AppGraph` の `StateFlow` で共有する。材料は `StripInsets` と同じ窓の座標(ダブルタップでも即座に更新される)。
  - 分割でない(全画面)→ `Full`。分割で窓の左端が画面の左端(x=0)に接する → `Left`、右端が接する → `Right`。
- 使い道: ドックの位置(§5)、リンクでブラウザを出す側(§6)、入れ替えの保存(§3.3)。
- PanelActivity が無い(パネルが出ていない)ときは `Full` 扱いではなく「不明」(`null`)とし、使う側は記録の組で代わりに判断する。

## 5. パネルの見た目
- `PanelContent`: `PanelSide.Left` のときは Row の並びを「ドック | 時計・切り替え・ミニプレイヤー・一覧」にする。`Right`・`Full`・不明は今のまま。ドックの中の並び・時計など内容の向きは変えない(文字は左寄せ)。
- 帯との重なりは今の `stripSafePadding` がそのまま効く(左のドックは左の帯の内側)。
- 入れ替えで側が変わったら、作り直しなしでドックが反対側へ移る(Compose の状態で描き直す)。
- 全画面のホーム・狭いホームは変えない。
- 画面セットのカード(`HomeSetCards.SetBlock`): パネルが左右どちらでも描く。マスの幅はセットの比率。`PanelIcon` は左パネルのとき**左右反転**した図柄(ドックが左)にする。名前は実際の並び。
- 幕・起動画面の予告: 入力(`SetRunner` が作る左右のマス)をセットの実際の並びで作る。描く側(`CurtainContent`・`BootScreen`)は左右共用のまま。

## 6. リンク
- 前面が「パネルを含む分割」のとき、ブラウザは**パネルがあった側**に出し、リンクを押したアプリは反対側に残す。比率 5:5。
  - 右パネル: 「アプリ | ブラウザ」(今と同じ)。左パネル: 「ブラウザ | アプリ」。
- 側の判断は §4.4 の `PanelSide`(無ければ記録の組)。
- 前面の組の相手は「組のうちパネル(中継)でない方」。左パネルで中継を相手と取り違えない。
- `LinkRouter` の前面の種類と経路に向きを持たせる(例 `AppPanel(app, panelSide)`、`SplitWithBrowser(app, browserSide)`)。`SetRunner` のリンク用の分割も、ブラウザの側を受け取る。
- 全画面のアプリから・両方アプリの分割から・ホームからは今のまま。

## 7. テスト

### 7.1 ユニットテスト(Robolectric)
- 設定: 版2の JSON(左 `{"pkg":…}`)→ 版3 に移行して読める。左パネルの保存・読み直し。両方パネルは弾く。
- 設定画面: 左右それぞれでパネルを選べる。片方をパネルにすると他方はアプリに固定。⇄ で左右と比率が反転。一覧の名前。
- 分割の起動: 左パネルで中継を左に渡す。`waitBoth` が左右どちらでも成立。逃がし先(反対側のアプリを全画面・未インストールならホーム)。
- 入れ替えの保存: 側が変わると左右と比率が入れ替わって保存。保存しない条件(パネルが無い・相手のアプリが違う・開いている最中)。
- パネルの見た目: `Left` でドックが左端。側の変化でドックが移る(作り直しなし)。
- リンク: 左パネルで「ブラウザ | アプリ」、右パネルは今のまま、中継を相手と取り違えない。
- ホームのカード・幕: 左パネルのセットの描き方。`PanelIcon` の反転。
- 既存のテストは意味を変えずに通す(「左はアプリ固定」を前提にした期待値だけ合わせる。どれを変えたか報告させる)。

### 7.2 実機の場面テスト(`scripts/device-scenarios.sh` に足す)
- 左パネルのセットを冷えた/温まった状態で開く(純正ホーム・YLuncher ホーム)。
- 左のパネルからアプリを起動 → 右に出る(デバッグの受け口を足す: `--es launch <pkg>`)。
- 左パネルの分割で右のアプリからリンク → 「ブラウザ | アプリ」。
- 仕切りのダブルタップ(`input tap` 2回。仕切りの位置は `dumpsys activity activities` の左右の枠から求める)→ `swapSaved` のログ、セットが保存される、ドックが反対側。
- 左パネルのセット ⇄ 右パネルのセットの切り替え。
- 既存の 14 場面が合格のまま。
- テスト用のセット(左パネル)は、場面テストの準備で設定に足すか、既存のセットを使う(実装の計画で決める)。終わったら元に戻す。

- 左パネルのときのドックの位置と帯との重なり。ダブルタップで入れ替えたときの動きの自然さ。
