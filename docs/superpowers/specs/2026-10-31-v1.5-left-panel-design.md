# YLuncher v1.5 左パネル対応 設計書

- 日付: 2026-10-31
- ブランチ: `v1.5`(v1.0 = タグ `v1.0`、右パネルのみの構成)
- 元の仕様: `docs/superpowers/specs/2026-10-28-gt8d-launcher-design.md`(r2.2)。本書はその差分。

## 1. 目的と要件(ユーザーの判断)

1. 画面セットごとに、パネルを**左にも右にも**置ける(「パネル | アプリ」「アプリ | パネル」「アプリ | アプリ」)。パネルは片側だけ。
2. 左パネルのときは、パネルの中の**ドック(右端バー)も左端**に置く(パネルを左右反転)。全画面のホームは変えない。
3. 左パネルのとき、パネル(ドック・アイコン一覧・ミニプレイヤー等)から起動したアプリは**右側**に出る。
4. 左パネルの分割で、右のアプリからリンクを押したら「**ブラウザ | アプリ**」で開く(今の動きの左右反転)。
5. システムの**仕切りのダブルタップ**で左右を入れ替えたら、その並びを**画面セットに保存**する。

## 2. 実機での確認(2026-10-31 実験。コードは残していない)

| 実験 | 結果 |
|---|---|
| ① 温まった状態で E に `com.gt8d.launcher.panel|com.google.android.youtube`・`2:3` | 中継のタスクが左 0..768px(40%)、中に PanelActivity。YouTube が右 783..1920。比率は左:右の順でそのまま効く |
| ② ①の左パネルのアイコン一覧からマップを起動 | マップは右(反対側)に出て、左のパネルは残る。今の `NEW_TASK | LAUNCH_ADJACENT | MULTIPLE_TASK` のまま |
| ③ 冷えた状態(本体・中継を force-stop)で①。既定のホームが純正/YLuncher の両方 | どちらも成功。SystemUI の異常終了なし。YLuncher のホームのタスク(affinity `com.gt8d.launcher.home`)はホームの場所に残り、分割に混ざらない |
| ④a 左パネルのまま右を YouTube → マップ | 成功。中継のタスクはそのまま |
| ④b 左パネル → 「YouTube | 中継」(3:2) | 成功。中継のタスクが左から右へ移る |
| ⑤ 「YouTube | パネル」で仕切り(x=1152..1167)の中央をダブルタップ(adb で `input tap` 2回) | 左右が入れ替わる(`onDoubleTappedDivider splitSwitching`)。パネルは幅 753px を保って左へ。PanelActivity は**作り直されない**(描き直しのみ)。`[Layout] strip window=(0,36-753,1080) pad=(48,0)` が直後に出る = 窓の位置の変化をアプリが捉えている |

結論: E・中継アプリ・隣に開く起動は、そのまま左パネルに使える。直すのはアプリ内の「パネルは右」の決め打ち。

## 3. データと設定画面

### 3.1 セットの型(設定の版 2 → 3)
- `ScreenSet(id, left: Slot, right: Slot, ratio, appPairLabel)`。`left` を `Slot.App` から `Slot` に広げる。
- 制約: `left` と `right` の両方が `Slot.Panel` のセットは保存しない(検証で弾く)。
- 比率は今までどおり**左:右**。パネルを含むセットの比率は `SplitRatio.forPanel`(4:6 / 5:5 / 6:4)。判定を `allowedFor(right)` から「左右のどちらかがパネルか」に変える(`allowedFor(set)` など)。
- 移行: 版 2 の JSON の `left` は `{"pkg": "..."}`(型の印なし)。`ConfigCodec.decode` で、版 3 未満なら各 `left` に `"type":"com.gt8d.launcher.config.Slot.App"` を足してから読む。
- 移行の確定の順番(`ConfigRepository`): ① 元の JSON を `config-v2-backup.json` に**一時ファイルへ書いて読み直して確かめてから改名**(原子的に)。既に正しいバックアップがあれば上書きしない(壊れていれば作り直す)。② ①が成功したときだけ、版 3 で書き戻す。①が失敗したら、メモリ上は版 3 で使い、ディスクは版 2 のまま(次回また移行を試みる)。
- 両方パネルのセットは読み込み時に除く(ログを出す)。
- **v1.0 に戻すとき**: v1.0 は版 3 を読めず既定値になる。戻す前に `config-v2-backup.json` を設定ファイルに書き戻す手順を、導入手順書に書く(`run-as` で。移行の後に v1.5 で変えた内容と、左パネルのセットは失われる)。
- `Defaults`(既定のセット)は変えない(左 YouTube・右パネル・6:4)。

### 3.2 設定画面(画面セットの編集 `SetsScreen`・`SetsEdit`)
- 左・右それぞれに「アプリ / パネル」の切り替えを置く。片方をパネルにすると、もう片方はアプリに固定(パネルを選べない)。
- **⇄(左右を入れ替える)**ボタン: 左右の Slot を入れ替え、比率を反転(3:7↔7:3、4:6↔6:4、5:5 はそのまま)。§3.3 と同じ規則。
- 一覧の名前は実際の並び(例「パネル | YouTube」)。
- 編集データ(`SetsEdit`)も左右対称に持つ(左がパッケージ文字列固定をやめる)。保存の条件・比率の補正・新規の初期値を左右対称に。

### 3.3 ダブルタップの入れ替えの保存
変化を1回ずつ拾うのではなく、**「落ち着いた実際の位置」と「セットのパネルの側」を比べて合わせる**(収束させる)。素早い2回の入れ替え・作り直し・通知の取りこぼしに強くするため。

**保存してよい区間(セッション)**
- 始まり: パネルを含むセットが**正常に開いた**とき(`waitBoth ready` → 幕が `Ready` で外れた)。区間は、セットの id・開いた時点のセットの内容(スナップショット)・相手のアプリ(パネルの反対側)を持つ。
- 終わり: ホームへ、次のセットを開き始めた、リンクで分割を作り始めた、起動の失敗・Safety・逃がし先、パネルが全画面になった(`Full`)、プロセスの終了(区間はメモリだけ。再起動後は保存しない)。
- 相手の更新: パネルからアプリを開いたら(ドック・アイコン一覧・アプリ一覧・ジャケット)、区間の相手をそのアプリに替える。

**保存の判断**(区間の中で、パネルの位置が `Left`/`Right` で 500ms 変わらなかったとき)
1. 位置の側 ≠ スナップショットのパネルの側 であること(同じなら何もしない)。
2. 区間の相手 == スナップショットのアプリ であること(パネルから別のアプリに替えていたら保存しない)。
3. 保存の処理の中で最新の設定から id でセットを探し、**スナップショットと同じ内容**(左右・比率)であること。変わっている・消えている → 保存せず区間を終える。
4. 1〜3 を満たせば、`swapped()`(左右と比率を反転、`appPairLabel` は null)で保存し、スナップショットを保存後の内容に替える。`lastOpenedPair` も入れ替える。
- 保存は順番に1つずつ(直列)。保存中に位置が変わっても、保存の後にもう一度 1 から判断する(最後の位置に収束する)。
- ログ: `DiagLog.d("SetRunner", "swapSaved id=<id> panel=<Left|Right>")`、保存しなかったときは理由付きで `swapSkipped reason=...`。
- 両方アプリのセットの入れ替えは、アプリから観測できないため保存しない(その場限り)。
- 設定画面で古い編集内容(入れ替え前に開いた編集)を後から保存した場合は、その編集が勝つ(ユーザーの明示の操作を優先)。

## 4. 分割の起動と、パネルからのアプリ起動

### 4.1 セットを開く(`SetRunner`)
- パネルのある側に中継アプリ `com.gt8d.launcher.panel` を入れて `VendorBridge.openSplit(left, right, ratio)` に渡す(`VendorBridge` は変えない)。
- `Opening`・`lastOpenedPair` は実際の左右の順で持つ。
- 成立の判定 `waitBoth`: 「アプリ側の Resume(UsageEvents)」+「PanelActivity の合図(`panelResumedInSplit`)」で成立、を左右どちらのパネルでも使う。呼び直しの抑止(`retry skipped`)も左右どちらでも効かせる。

### 4.2 逃がし先
- パネルを含むセットで、分割が使えない・起動に失敗: **パネルの反対側のアプリ**を全画面で開く。
- パネルを含むセットで、そのアプリが入っていない: ホームへ。
- 両方アプリのセット: 今のまま(左のアプリを全画面、右が無ければ左だけ)。

### 4.3 パネルからアプリを開く
- 起動の仕方は変えない(実験②)。起動に成功したら `SetRunner` に知らせ、`lastOpenedPair` の相手と §3.3 の区間の相手をそのアプリに替える(`fun panelLaunched(pkg: String)`)。

### 4.4 パネルが自分の側を知る
- `PanelActivity` が自分の窓の画面上の位置から `PanelPlacement { Left, Right, Full }` を決め、`AppGraph` の `StateFlow` で共有する。材料は `StripInsets` と同じ窓の座標(ダブルタップでも即座に更新される)。画面の幅は `WindowManager.maximumWindowMetrics` の幅。
  - 判定の順: 分割でない → `Full`。窓が画面の両端に接する(全幅) → `Full`。左端(x≤0)だけ接する → `Left`。右端だけ接する → `Right`。どちらにも接しない(移り変わりの途中) → `null`(不明)。
- 使い道: ドックの位置(§5)、リンクでブラウザを出す側(§6)、入れ替えの保存(§3.3)。
- PanelActivity が無い(パネルが出ていない)ときは `Full` 扱いではなく「不明」(`null`)とし、使う側は記録の組で代わりに判断する。

## 5. パネルの見た目
- `PanelContent`: `PanelSide.Left` のときは Row の並びを「ドック | 時計・切り替え・ミニプレイヤー・一覧」にする。`Right`・`Full`・不明は今のまま。ドックの中の並び・時計など内容の向きは変えない(文字は左寄せ)。
- 帯との重なりは今の `stripSafePadding` がそのまま効く(左のドックは左の帯の内側)。
- 入れ替えで側が変わったら、作り直しなしでドックが反対側へ移る。内容(時計〜一覧)は**同じ composition の位置のまま**並びだけを変える(Row の並べ方を変える。内容を条件分岐の別の枝に置かない)。一覧のスクロール位置・アプリ一覧の開閉・セグメントの選択が保たれること。
- 全画面のホーム・狭いホームは変えない。位置は `PanelActivity` からだけ `PanelScreen` に渡し、ホーム(`HomeActivity`)は常に `null` を渡す。
- 画面セットのカード(`HomeSetCards.SetBlock`): パネルが左右どちらでも描く。マスの幅はセットの比率。`PanelIcon` は左パネルのとき**左右反転**した図柄(ドックが左)にする。名前は実際の並び。
- 幕・起動画面の予告: 入力(`SetRunner` が作る左右のマス)をセットの実際の並びで作る。描く側(`CurtainContent`・`BootScreen`)は左右共用のまま。

## 6. リンク
- 前面が「パネルを含む分割」のとき、ブラウザは**パネルがあった側**に出し、リンクを押したアプリは反対側に残す。比率 5:5。
  - 右パネル: 「アプリ | ブラウザ」(今と同じ)。左パネル: 「ブラウザ | アプリ」。
- 側の判断は §4.4 の `PanelSide`(無ければ記録の組)。
- 前面の組の相手は「組のうちパネル(中継)でない方」。左パネルで中継を相手と取り違えない。パネルからアプリを替えた後は、替えた後のアプリ(§4.3)。
- **組にブラウザが入っている分割**(リンクで作った「ブラウザ | アプリ」「アプリ | ブラウザ」)からまたリンクを押したら、ブラウザの側はそのまま、反対側のアプリを残して同じ並びで開き直す(全画面にしない)。
- `LinkRouter` の前面の種類と経路に向きを持たせる(例 `AppPanel(app, panelSide)`、`SplitWithBrowser(app, browserSide)`)。`SetRunner` のリンク用の分割も、ブラウザの側を受け取る。
- 全画面のアプリから・両方アプリの分割(ブラウザを含まない)から・ホームからは今のまま。両方アプリの分割を仕切りで入れ替えた後は、アプリから並びが分からないので、記録の並びのまま扱う(既知の制約)。

## 7. テスト

### 7.1 ユニットテスト(Robolectric)
- 設定: 版2の JSON(左 `{"pkg":…}`)→ 版3 に移行して読める。左パネルの保存・読み直し。両方パネルは弾く。
- 設定画面: 左右それぞれでパネルを選べる。片方をパネルにすると他方はアプリに固定。⇄ で左右と比率が反転。一覧の名前。
- 分割の起動: 左パネルで中継を左に渡す。`waitBoth` が左右どちらでも成立。逃がし先(反対側のアプリを全画面・未インストールならホーム)。
- 入れ替えの保存: 落ち着いた位置がセットと逆なら左右と比率を反転して保存。素早い2回で元に戻る(保存を遅らせても最後の位置に収束)。保存しない: 区間の外(開いている最中・Safety・失敗・ホーム・リンク・プロセス再起動後)、パネルからアプリを替えた後、設定でセットが変わった/消えた、全幅・不明の位置。
- 設定の移行: バックアップを確かめてから版3を書き戻す。バックアップに失敗したらディスクは版2のまま。既存の正しいバックアップは上書きしない。
- パネルの見た目: `Left` でドックが左端。側の変化でドックが移り、スクロール位置などの状態が保たれる。狭いホームは位置に関係なく右。
- リンク: 左パネルで「ブラウザ | アプリ」、右パネルは今のまま、中継を相手と取り違えない、パネルからアプリを替えた後は替えた後のアプリ、ブラウザを含む分割から2回目のリンクで同じ並び。
- ホームのカード・幕: 左パネルのセットの描き方。`PanelIcon` の反転。
- 既存のテストは意味を変えずに通す(「左はアプリ固定」を前提にした期待値だけ合わせる。どれを変えたか報告させる)。

### 7.2 実機の場面テスト(`scripts/device-scenarios.sh` に足す)
- 左パネルのセットを冷えた/温まった状態で開く(純正ホーム・YLuncher ホーム)。
- 左のパネルからアプリを起動 → 右に出る(デバッグの受け口を足す: `--es launch <pkg>`)。
- 左パネルの分割で右のアプリからリンク → 「ブラウザ | アプリ」。
- 仕切りのダブルタップ(`input tap` 2回を1つの `adb shell` で。仕切りの位置は `dumpsys activity activities` の左右の枠から求める)。システムのログ `onDoubleTappedDivider` で入れ替えが起きたことを先に確かめ(起きなければ1回だけやり直し、それでも無ければ「入力が効かない」で不合格)、次に `swapSaved`、`[Panel] placement=` が反対側、設定ファイル(`run-as` で読む)のセットの左右と比率が入れ替わっていること。もう一度ダブルタップして元に戻ること。
- 左パネルのセット ⇄ 右パネルのセットの切り替え。
- 既存の 14 場面が合格のまま(リンクのログの文言が変わる分、判定を新しい形に合わせる)。
- 場面テストの最初に設定ファイルを `run-as` で退避し、終わり(途中で失敗しても `trap` で)書き戻してアプリを止め直す。次回の開始時に退避が残っていたら、先に書き戻す。テスト用の左パネルのセットはデバッグの受け口で足す。

### 7.3 お手元での確認
- 左パネルのときのドックの位置と帯との重なり。ダブルタップで入れ替えたときの動きの自然さ。

## 8. 範囲の外
- 全画面のホームの左右反転。
- 両方アプリのセットの入れ替えの保存。
- 予備方式 D(アプリペア)の左パネル対応(Task 19 で扱う)。今は D の配線が無い(`appPair = null`)。入れ替えたセットは `appPairLabel` を null にし、左パネルのセットを D に渡さない(D の失敗時は反対側のアプリを全画面)ことを、Task 19 の前提として残す。
- 両方アプリのセットの入れ替えの保存と、入れ替えた後のリンクの並び。
- プロセスが終わった後の入れ替えの保存(区間はメモリだけ)。
