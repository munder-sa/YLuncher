## 1. 目的と継承する仕様

v2.0.0 は、ジャケット由来の暗い静止グラデーション、現在行・次行の明暗、可視行の短い時間差、非現在行の控えめな縮小を加える。

現行は 22sp・Bold・左揃え・最大2行・行間16dp、現在行を中央へ800msで送る。明るさは500msの `FastOutSlowInEasing`。これを基準にする。旧 §5.2 の24sp・300msや、単語時刻のない行を時間で塗る方式には戻さない。単語時刻のある行だけの塗り、間奏・長い前奏の3点、上下32dpのフェード、Plain の静止表示、Loading、取得失敗時のジャケットへの復帰は維持する。

タッチ72dp、本文20sp以上、歌詞領域120dpの境界、カードの寸法・余白段階・曲送り・☆・シークバー・設定と通信条件は維持する。曲名・アーティストの既存マーキーも今回の変更対象外。

## 2. Global Constraints

- GT8D は全画面の描画が GPU 側で約50ms/フレームを要する実測がある。既存資料の動作中の間隔は約53ms。これを60fps達成の課題とはせず、常時描画する演出を追加しない。
- Task 142〜145 の構造を保つ。動きは `graphicsLayer`・`placeRelativeWithLayer` で行い、アニメーション値を composition・measure・placement の本体で読まない。行変更・サイズ変更時の計測と、毎フレームの再計測を区別する。
- Task 145 のリリース版の「画面全体をユーザー補助に『パネル』1つとして見せる」構造を保つ。テスト用の行別プローブをリリース版の semantics に出さない。
- 新規ライブラリなし、BuildConfig の有効化なし。既存 Kotlin・Compose・coroutines・Android Bitmap の機能だけを使う。
- 開発ブランチは `v2.0`。版名は `2.0.0-betaN`、最後は `2.0.0`。版コードは各配布で単調増加。ブランチ操作・コミット・main 取り込み・タグ・公開は司令塔が行う。
- ビルド・テストは `/home/munde/tools/gradle-run.sh`。絞り込みは `:app:testDebugUnitTest --tests '...'`。codex は adb を実行しない。触ったパッケージだけを検証し、全テストは最後に1回。

## 3. ジャケットから作る静止背景

### 3.1 色抽出

ホームのミニプレイヤーのカード全面に適用する。歌詞表示のオン/オフ・再生/停止には連動しない。待ち受け・ジャケットなし・抽出不能は `Palette.Panel` (`#2E2E38`) の単色。成功時も曲変更時も背景のクロスフェードはしない。

自前の粗い RGB ヒストグラムを用いる。平均色だけで補色が混ざることを避け、同じ入力は必ず同じ出力にする。

1. ワーカー上で画像の縦横比を保ち、長辺を最大32px、短辺を最低1pxに縮小する。拡大しない。読み取り用の一時画像はソフトウェアの ARGB_8888 とし、Bitmap API のコピー・画素読み取り失敗はフォールバックする。ハードウェア Bitmap はワーカー上で読み取り用コピーを試す。MediaWatcher 所有の元画像は変更・recycle しない。
2. A < 128 の画素は除外。A ≥ 128 の画素は RGB を使い、重みを A/255 とする。透明部分を黒で埋めて集計しない。
3. RGB各成分を0〜255とし、`max-min < 24` の無彩色に近い画素、`max < 32` の暗い画素、`min > 224` の白に近い画素は除外する。境界の24・32・224は除外条件の不等号に従う。白黒主体でも有効画素が1つあれば候補にでき、ゼロならフォールバック。
4. 各成分の上位4bit(16段階)で4096箱に分け、重みの合計が最大の箱を選ぶ。同数なら RGB の箱番号が小さい方。代表色はその箱の重み付き RGB 平均を四捨五入した値。
5. 同一画像から第2の主要色は取らない。1つの代表色から暗さの異なる2色を作る。処理量は縮小後最大1024画素、箱数4096で上限を持たせる。

例外はキャンセルを再送出し、読み取りに関する例外・一時画像の確保不能ではフォールバック。無制限の再試行はしない。一時画像だけを finally で解放する。同一オブジェクトが返る縮小処理でも元画像を誤って解放しない。

### 3.2 暗色化と形

代表色を `(r,g,b)`、`m=max(r,g,b)>0` とし、各成分 c について明るい端を `round(24+32*c/m)`、暗い端を `round(12+16*c/m)` とする。不透明な sRGB とし、明るい端は各成分24〜56、暗い端は12〜28。色相の違いを弱く残しつつ暗く制限する。

カード左上(0,0)の明るい端から右下(width,height)の暗い端への、2色・1本の線形グラデーションを描く。多層の放射・メッシュ・ぼかしは使わない。`drawWithCache` でサイズと2色が変わったときだけ Brush を作り直し、Surface の角丸24dpの内側、padding より外側まで塗る。背景を別の不透明な `Palette.Panel` で隠さない。

例: 赤 `(255,0,0)` → 明 `#381818` / 暗 `#1C0C0C`。緑 → `#183818` / `#0C1C0C`。この変換とフォールバックの全成分は56以下になるため、§4では保守的な背景上限 `#383838` も検証する。これは計算上の設計条件であり、描画結果の測定済みという意味ではない。

### 3.3 計算時機・保持・競合

`MediaWatcher` は既に ALBUM_ART → ART の順で Bitmap を渡す。今回そこで色計算を行わず、ホーム用の状態保持部品から `Dispatchers.Default` で抽出する。

- 画像の鍵は Bitmap の参照同一性と `generationId`。曲の鍵は `(pkg, metaTitle, artist, album, durationMs)` の生値。曲の同一性を歌詞取得可否だけで判定しない。
- 同じ画像のまま位置・再生状態・曲情報だけが変わっても再抽出しない。曲の鍵は結果の適用先の識別に用いる。同じ画像の抽出中に曲だけ変わった場合も、適用先を更新し最新の要求世代でだけ反映する。
- 画像変更時だけ抽出。新画像の処理中は Panel に戻し、以前の画像の色を新画像の色として出さない。画像が同じなら保持済みの2色を再利用する。
- 画像・曲・非表示化・再生情報の消失ごとに要求世代を更新。キャンセルだけに頼らず、完了時に世代と画像の鍵、最新の曲の鍵を照合する。A→B→A の順でも最初の A の遅い完了は捨てる。
- メモリに保持するのは現在の画像の鍵と結果1件のみ。ディスクキャッシュ、全曲キャッシュ、再生位置ごとの計算なし。失敗結果も同じ画像の間は保持し、毎回再試行しない。
- 表示を離れたらジョブをキャンセルし結果の適用を無効にする。再表示時には部品の生存期間内なら保持済み結果を使用し、破棄後は現在の画像について1回計算する。

Bitmap の差し替えや破棄と読み取りが競合してもクラッシュしないことは Robolectric と実機で確認する。API の成功を前提にせず、読めない場合は上記フォールバックを使う。

## 4. 現在行・次行の明るさとコントラスト

初期値は1か所の `LyricsVisualStyle` にまとめる。

| 対象 | 白の目標 alpha | 扱い |
|---|---:|---|
| 現在行(単語時刻なし) | 1.00 | 行全体を強調 |
| 現在行(単語時刻あり)の未塗り部分 | 0.62 | 塗った部分は1.00、実際の重ね合わせも検証 |
| 次行 | 0.62 | 主要文字として読める明るさ |
| 直前行 | 0.45 | 補助的な表示 |
| 距離2の行 | 0.35 | 遠方の表示 |
| 距離3以上 | 0.25 | 遠方の表示 |

最初の行より前は行0を次行相当0.62、以後はその行からの距離で0.45・0.35・0.25とする。前奏の3点表示は現行条件を保つ。間奏の点灯済み1.0・未点灯0.35、過去の点の表現は現行を維持する。Plain は白1.0、Loading・アプリ名・アーティスト・時刻・失敗理由の `Palette.Muted` は `#B0B0BB` のまま。

通常の次行移動時は明るさを500msで目標値へ。送りの時間差を明るさには適用しない。現在行になる行は変更前から0.62なので、1.0へのフェード中も主要文字の条件を満たす。飛び・戻り・初期表示・曲替え時は即時反映。単語塗りの境界や強調の重ね合わせで0.62を下回らせない。

### 4.1 判定方法

主要な文字(現在行・次行・Plain・タイトル)と補助情報(`Palette.Muted`)は4.5:1以上を目標にする。alpha を色の明るさとして直接比較せず、各 sRGB 成分を `out = alpha*foreground + (1-alpha)*background` で合成してから相対輝度を求める。成分 s を0〜1として、s≤0.04045なら s/12.92、それ以外は `((s+0.055)/1.055)^2.4`。輝度は `0.2126R+0.7152G+0.0722B`、比は `(明るい輝度+0.05)/(暗い輝度+0.05)`。

抽出色の両端・途中(少なくとも t=0,0.25,0.5,0.75,1)、フォールバック、保守的上限 `#383838` を対象に、白・Muted・白0.62・500msフェードの最小値をテストする。実際の8bit丸めを含めた値を使う。旧0.45と新0.62の比較も記録し、4.5未満なら主要文字用定数を上げるか背景をさらに暗くする。閾値を下げない。

過去・遠方行、未点灯の点、上下32dpで消えていく部分、無効状態のボタンは4.5保証対象外。これらも合成色と比を記録し、主要な文字と取り違えない。文字のアンチエイリアスの端ではなく塗り内部で判定する。現在行中央と、フェードに掛からない次行は必須。狭い領域で次行が端フェードに掛かる場合は、4.5を満たすと報告せず、実機記録に残す。領域拡張や端フェード変更は別の仕様判断とする。

## 5. 可視行だけを少し遅らせる送り

通常の `oldIndex → oldIndex+1` のみ対象。現在行は遅延0ms、その他は新しい現在行からの距離 d に対して `min(d*50,100)ms`。各行の移動時間は既存の800ms、`FastOutSlowInEasing`、従って全体は最大900msで収束する。ばねへの変更や跳ね返りは加えない。

- 対象は「変形前の行の矩形が、移動開始位置または到着位置で歌詞領域と交差する行」の集合。境界に接するだけは不可視。可視集合は行変更・サイズ変更時に計算し、毎フレーム計測しない。途中から入る行も到着位置の交差で含める。
- 現在行は必ずアニメーション対象。集合外の行は目標位置へ即時に置き、遅延ジョブや Animatable の更新を持たせない。可視行だけの移動であり、全行を描画する既存 Layout を Lazy 化する変更はしない。
- 次の行へ進む判定時、各行の実際の表示座標を層の状態から採取し、旧ジョブを取り消し、その座標を新しい始点とする。新しいレイアウト基準への差を同じ更新で補正し、開始時点で表示座標が変わらないようにする。待機中に再変更された行も同様。
- 2行以上の前方飛び、戻り、曲・歌詞リストの変更、初回表示、サイズ変更では遅延と移動をすべて取り消し即時配置。最初の行前の -1→0 は同じ中心を保ち、不要な移動を作らない。端末のアニメーション倍率0では待機も含め即時完了。それ以外は端末設定に従う。
- 計測された行の高さ・16dp間隔は変えない。行変更のときだけ到着座標を更新し、フレームごとの補間値は `placeRelativeWithLayer` の層ブロックで読む。

行ごとの遅れにより瞬間の行間が変わるため、1行/2行折り返し混在と連続する短い行で重なりを確認する。安全でない組では、その遷移の遅延を全行0にして既存の共通送りへ戻す。判定は独立した計算関数にし、開始時に次の保守的な十分条件を使う。

隣接行a,bの変形前の到着間隔を `g = targetTop[b]-targetTop[a]-height[a]`、移動量を `Da/Db = targetTop-startTop`、遅延差を `dt=abs(delay[a]-delay[b])` とする。全隣接組で `g - abs(Db-Da) - min(abs(Da),abs(Db))*min(1,4*dt/800) >= 0` の場合だけ時間差を使う。これは補間の最大傾きを4以下とする保守的な変位差の上界であり、指定の FastOutSlowInEasing の cubic-bezier(0.4,0,0.2,1) に限定する。補間曲線を変更するときはこの上界も再検証する。NaN・無限値・不正な高さ等は不合格とする。判定不能な遷移も全行の遅延を0にする。遅延0の共通補間は開始/到着それぞれの行順を保つ。800msの送りと途中再目標化は維持する。

## 6. 非現在行の縮小

初期値は現在行1.0、その他0.97。`LyricsVisualStyle.InactiveScale` に集約し、実機で0.96〜0.97から決める。文字22sp、測定された高さ、改行・省略・16dpの間隔・中央座標の計算には縮小値を使わない。

行全体(本文・単語塗り・間奏の点を含む)の `graphicsLayer` で scaleX/scaleY を同じ値にし、`TransformOrigin(0f,0.5f)`(左の縦中央)を使う。通常の次行移動だけ500msで補間し、待ち時間なし。途中変更は現在の scale から再目標化。飛び・戻り・曲替え・初期表示は即時。最初の行前に現在行はないので全行0.97。Plain・Loading と MediaCard の1行歌詞には縮小・時間差を適用しない。

## 8. 実機確認と受け入れ

計測は人/司令塔が実施し、codex は取得済み記録を読む。人が gfxinfo のフレーム統計と Perfetto の FrameTimeline・UI thread・RenderThread・GPU 関連の利用可能なトラックを採取する。端末で取得できない項目は未測定とする。ここでは adb の実行を許可しない。

v1.7.1 と各 beta を、同じ端末・解像度・分割比・フォント/アニメーション倍率・温度条件・再生アプリ・曲・歌詞キャッシュ状態で比較する。ウォームアップ後の同一区間60秒を各3回。Apple Music と YouTube Music、行同期/単語同期/間奏を分ける。

- フレーム間隔 p50/p90/p95、jank率、UI thread/RenderThread/GPUの処理時間、長いフレームの位置、曲替え時の抽出時間・メインスレッド停滞を比較する。約50msの端末限界と新しいCPU作業の増加を分ける。
- 行変更後の800〜900msの動作区間と、動作のない停止区間を分ける。停止区間で背景・行同期歌詞由来の連続フレーム要求が増えないこと。既存シーク・マーキー・単語塗りの更新は別に記録する。
- `LyricsPaneObserver` の compositions/measures/placements/frameUpdates を使用し、行の切替処理を済ませた後、動作フレームだけでは最初の3つが増えないこと。行同期の通常待機で frameUpdates も増えないこと。
- 見た目: 赤/青/緑/補色混在/白黒/透明/欠落ジャケット、連続曲送り、Loading・失敗、停止・再開、最初/最後の行、2行折り返し、100ms間隔の行、シーク前後、送り途中の変更、狭い120dp付近、☆と切替ボタン、分割画面を確認する。
- 左端が動かないこと、現在行が中央へ収束すること、次行が読めること、瞬間の跳び・文字の重なりがないこと、縮小0.97/0.96の可読性、端フェードの例外を記録する。

自動検証の必須条件は主要文字比4.5以上、遅延0/50/100ms、最大900msで収束、非現在行の初期値0.97、フレーム単位の再組立て/再計測/再配置なし、古い色の反映なし。実機の定量的な性能退行許容幅は未決。初回の対応する記録で司令塔とユーザーが決めるまで、性能合格と判定しない。定数の最終値と beta の採否も実機後に決める。
