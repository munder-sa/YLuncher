# v2.1.0 の次版 描画・処理負荷の削減 設計書

- 日付: 2026-11-04

## 1. 目的・継承する仕様

ホーム復帰時の同期処理、歌詞の構築・計測・描画層の数を減らす。対象は歌詞の構築範囲、重ね文字、共有アプリ情報、配布ビルドの最適化の4点。見た目・操作・設定形式を変えない。

22sp・Bold・左揃え・最大2行・16dp間隔、800msの送り、500msの明暗、現在の時間差・縮小・単語塗り・間奏・前奏を維持する。Plain・Loading・取得失敗・120dp境界・タッチ領域・背景共有も維持する。v1.7.1/v2.0 の層による移動を継承し、アニメーション値は描画または層で読む。毎フレームの composition・measure・placement を発生させず、measure・layout から snapshot state に書き込まない。

既存ライブラリのみ使用する。ベースラインプロファイルに必要な追加依存は §6 の承認事項。codex は adb、ネットワーク、コミット・リセット・ブランチ操作を行わない。

## 2. 現行コードで確認した負荷

- `LyricsPane.kt`: `state.lines.forEachIndexed` で全行を構築し、Layout 内で全行を計測・配置する。alpha/emphasis の `LaunchedEffect(target, index)` は同じ目標値でも行番号変更で再起動する。
- 単語付き行は非現在行でも重ね Text と Offscreen を持つ。単語境界の horizontalGradient と領域全体の verticalGradient を draw 内で作る。領域全体の Offscreen は DstIn のために必要であり維持する。
- `PanelEnvironment.kt`: remember の初期化と DisposableEffect の末尾で `readEnvironment` を実行する。ON_RESUME で全アイコン・名前を消し、一覧を同期取得する。無線更新も一覧と同じ revision を進める。
- `AppCatalog.kt`: installed/launchables はそれぞれ問い合わせ、label/icon のキャッシュミスは同期処理。`PanelScreen.kt` には revision を鍵とする設定アプリ取得、アイコン取得、info 呼び出しがある。`HomeActivity.kt` の iconFor も移行点となる。
- app/panelhost は versionCode=37、versionName=2.1.0。両方とも release の minify は false。設定は `@Serializable`、`Slot` の sealed 階層と型識別子を含む。

## 3. 歌詞の構築範囲

### 3.1 行の高さと窓

一律の行数・推定の固定高で切らない。現在行をアンカーに、実際の折り返し高と16dp間隔を使って上下の必要な行を求める `LyricWindow` を導入する。全曲の Text/Placeable を先に作る方式は採らない。初回・シーク時は移動先の現在行と隣接行から、必要領域を覆うまで測定対象を外へ広げる。

文字の測定条件は描画と共通化する。高さのキャッシュキーは歌詞世代・行番号・幅・density・fontScale・文字スタイル・前奏表示種別。保持は現在の窓と遷移の保留行に限定し、曲の全行の TextLayoutResult や Bitmap を保持しない。幅・フォント条件の変更時は旧幾何を破棄し即時配置する。

構築範囲は、可視領域 `[0,H]` を上下それぞれ「今回の最大移動距離 D + 余裕 M」で拡張した領域と交差する行。D は現在の各表示座標と新しい到着座標との差の絶対値の最大、M は窓内の最大行高+16dpを初期値とする。新しい行の高さが M を上回る場合は再計算し、領域を覆うまで広げる。さらに現在行・開始時可視行・到着時可視行・進行中の旧遷移で保持中の行を必ず含める。非単調な行別時間差も、開始/到着矩形と移動経路全体を覆う包絡範囲で扱う。領域の上下32dpのフェード部分も可視領域に含める。

窓の計算・測定準備は行変更・歌詞変更・領域サイズ変更時に行う。測定結果は通常のデータとして受け取り、状態への反映は measure/layout の外で行う。幾何と窓と遷移を同じ世代の不変計画として渡し、未計測の移動先を表示してから後で中心を修正しない。SubcomposeLayout 等の API 採用を含む具体実装は Task 165 で既存 Compose と実験テストにより確認する。毎フレームの subcompose/measure は禁止。

### 3.2 遷移と寿命

行キーは歌詞世代と行番号。通常の次行送りは旧窓と新窓の和集合を先に準備し、層が最後に描いた座標を引き継いでから開始する。800ms+既存最大100msの遅延と500msフェードの全てが終わるまで、画面に入る可能性のある行を破棄しない。完了時の窓縮小は1回の構成更新として許す。途中で次行になった場合は実表示座標から包絡範囲を再計算する。窓内の隣接行を使う既存の重なり防止判定も維持する。

2行以上の飛び・戻り・シーク・曲替え・歌詞差し替え・サイズ変更は旧ジョブを無効化し、移動先の窓を準備して即時配置する。世代不一致の計測・完了通知を適用しない。最初/最後、-1→0、アニメーション倍率0も既存挙動を保つ。

alpha/emphasis は行キーと目標値、即時反映が必要な遷移世代を鍵にする。index だけでは再起動しない。同じ目標の遠方行はジョブを作らず、変更行のみ500msで補間する。シーク等では目標が同じでも進行中の旧補間を中止して即時反映する。新しく構築する行はその遷移の時刻から本来の値を得て、画面に入った瞬間にフェードを最初から始めない。

デバッグの `LocalLyricsDetailSemantics`、行タグ、alpha と draw probe、current/fill/interlude タグの意味と既存テストが観測する範囲を維持する。デバッグ詳細モードは従来どおり全行を構築する互換経路とし、窓最適化は無効にする。窓の性能試験は詳細 semantics をオフにし、observer/内部プローブで検証する。release は行別 semantics を追加せず、画面全体「パネル」1ノードを維持する。

## 4. 重ね文字と Offscreen

単語付きでも重ね Text を構築するのは現在行と強調が消える途中の旧現在行だけ。進行中に複数回切り替わればフェード中の各行を保持する。旧行の最終 fill を保持し、500msの強調終了時に重ね Text と専用層を外す。曲替え・シークの即時更新では旧重ね層を残さない。間奏の点は既存経路を維持する。

重ね層内の DstIn/Clear は他の文字を消さない独立した描画先を必要とするため、使用中の重ね文字の Offscreen は維持する。単純に Auto に置換しない。層数を必要な行に限定して削減する。基底文字のalpha、白の塗り、12dp幅の境界、2行目の消去、未塗り部分の見た目を変えない。

領域全体の上下32dpマスクは Offscreen を残し、`drawWithCache` でサイズ・density変更時にだけ Brush を生成する。単語境界は固定の黒→透明・幅24dpのグラデーションをキャッシュし、描画時に境界座標へ移す。進捗をキャッシュ構築部で読まず、描画部で読む。文字の折り返し・省略・行矩形へのクリップは現行と一致させる。ゼロサイズを含むキャッシュ再生成と描画の扱いはテストする。

## 5. 共有アプリ情報と PanelEnvironment

### 5.1 所有者と非同期取得

AppGraph の寿命で applicationContext を使う `AppCatalogState` を所有し、ホームとパネルが同じ不変スナップショットを購読する。PackageManager の一覧・ラベル読み取りは IO、Drawable→96px Bitmap変換はワーカーで行い、UI は保持済み値だけを読む。同じパッケージの取得は共有し、多重取得を防ぐ。一覧は1回の launchable 問い合わせ結果から installed と既存 buildAppList 用エントリを作る。並び・除外条件・設定アプリの表示規則は変えない。

既存 `installed/launchables/info/icon/label` の全利用箇所を調べ、ホーム/パネルの表示経路のキャッシュミスが同期取得へ戻らないよう移行する。AppGraph の利用履歴集計や他の起動処理の振る舞いの変更は含めない。config が指定する未インストールアプリ、設定アプリ、メディアのアプリも必要な取得対象に含む。

初回取得は所有者が1回だけ開始。再表示は前のスナップショットを即時利用し、重複リクエストを作らない。初回に有効な情報がない間は取得中を内部状態で区別し、空一覧を確定データとして設定に保存したり、アプリを未インストール扱いにしたりしない。既存の正常なカード表示を準備後に出し、新しいスピナー・配置変更は加えない。失敗時は最後の成功データを保持し、キャンセルは再送出する。初回失敗は未取得として保持し、次の復帰または対象イベントで1回再試行し、毎フレーム再試行しない。

### 5.2 失効・競合・revision

パッケージ receiver を画面の DisposableEffect から共有所有者へ移し、非表示中も ADDED/REMOVED/CHANGED を追跡する。これにより既存 `environment_resume_refreshesPackagesMissedWhileHidden` の目的を保持し、復帰の全再取得は不要にする。receiver の登録・解除を所有者の start/close と対応させ、Activity を保持しない。プロセス停止中の変更は次の初回取得で反映する。

失効は対象パッケージのイベント時だけ。ON_RESUME、Wi-Fi、Bluetooth、権限更新ではキャッシュを消さない。置換の REMOVED→ADDED も最終世代で整合させる。ロケール/密度等、アイコン・ラベルの入力条件が変わる場合はその構成世代だけを失効させる。無条件の復帰時全消去へ戻さない。

パッケージ別世代と一覧要求世代を持ち、取得中の更新・削除・A→B→Aでも古い結果を反映しない。一覧の更新要求は集約し、最新要求を落とさない。アイコン失敗結果も対象世代内で保持する。キャッシュは現行アプリ情報の世代だけとし、失効・削除で古い画像参照を外す。

`PanelEnvironment` の revision を `appRevision` と `radioRevision` に分離する。appRevision は一覧・名前・アイコンの確定更新、radioRevision は無線状態の確定更新でのみ進める。権限は専用の値を比較して通知する。ON_RESUME では権限と無線を更新する。`PanelScreen` の設定アプリ、appInfo、iconRevision、全 remember の鍵を分類し、Wi-Fi の変化が一覧問い合わせ・画像変換を発生させないようにする。非同期アイコン完了は appRevision でUIへ通知する。

## 6. 配布ビルド

### 6.1 R8

必須対象は app の release。`isMinifyEnabled=true`、`isShrinkResources=true`、既定の最適化ルールと専用 `app/proguard-rules.pro` を明示する。debug/Robolectric のビルド種別は変えず、テスト用クラス・Robolectric を release keep に追加しない。警告を一括で無視するルールは使わない。

設定互換の初期方針は保守的に `com.gt8d.launcher.config.**` のクラス名・メンバーと生成 serializer/Companion、シリアライズに必要な属性を保持する。`Slot.App`/`Slot.Panel` 等の型識別子と enum 名を維持し、既存 JSON・migration・encodeDefaults 等の codec 方針を変更しない。依存ライブラリの consumer rules と実際の生成物・mapping/usage を Task 168 で調べ、正確な keep 規則を確定する。既定ルールだけで十分とは断定しない。config 以外の反射・Manifest入口・リソース参照も実物を調べ、必要最小限を追加する。

Robolectric は縮小前コードの検証であり、それだけで R8 合格にしない。司令塔が署名の同じ2.1.0 releaseで設定を保存し、データを消さず縮小済みbetaへ更新する。画面セット(左右のApp/Panelと比率)、アプリ順、リンク/ジェスチャー/起動設定、歌詞オン等を更新前後で比較し、編集→保存→再起動後も保持されることを確認する。旧形式の設定移行も実機で確認し、JSONのキー・型識別子・値を照合する。バックアップと復旧経路を用意し、アンインストールで更新確認を代用しない。

panelhost も縮小するかは未決。小さい中継アプリの追加リスクを分離するため、初期推奨は app のみ。採用する場合は専用ルール・リリース成果物・中継起動/分割/ホーム復帰の実機検証を追加し、app のルールを流用して合格にしない。

### 6.2 ベースラインプロファイル（承認待ち）

`androidx.profileinstaller`、baselineprofile プラグイン、macrobenchmark モジュールは新規依存禁止の例外となる。ユーザーが承認するまで導入しない。見送りでも R8 と他の必須改善は進められる。

承認後に司令塔が既存 AGP/Gradle と互換のバージョン、モジュール/依存/許可ファイルを別指示書で確定する。司令塔が adb を使える実機で、ホーム起動・復帰、Apple Music の歌詞、パネル表示のシナリオを実行して生成し、プロファイル内容と release への同梱を確認する。生成済み成果物を codex が読む工程と、端末操作を分ける。実機でプロファイル適用あり/なしを同条件比較し、結果が未確認なら効果を報告しない。

## 7. 計測と受け入れ

人/司令塔が同じGT8D、解像度・分割比・フォント倍率・アニメーション倍率・温度・電源・曲と再生位置・歌詞キャッシュ状態で採取する。Apple Music 再生中・歌詞オン、ウォームアップ後の同一区間で **Perfetto 30秒、gfxinfo 30秒を各3回**。2.1.0と縮小済みbetaを前後比較し、v1.7.1以降の既存記録とも条件を揃えて比較する。

動作中のフレーム間隔とメインスレッドdoFrameのp90を必須とし、p50/p95・jank率・RenderThread/GPUの取得可能な値も記録する。静止と800〜900msの動作区間を分ける。既存の約53ms間隔・doFrame p90=10.7msは履歴であり今回の実測値ではない。v2.0で合意済みのv1.7.1比 +5ms/+5ポイントを既存の退行上限として継承し、本改修の改善量の目標は測定後に別途合意する。平均だけで各3回の退行を隠さない。

ホーム復帰は同じ遷移元・同じウォーム状態で、司令塔が `am start` 開始からホーム最初のフレームまでの時間を測り3回記録する。コマンドの応答時間だけを初回描画時間に置き換えない。冷起動は別枠にし、共有キャッシュの有無・アプリ数も記録する。

必須の構造的受け入れ:
- 詳細semanticsオフで、長い歌詞の構築・計測・層数が全行数ではなく窓に応じる。短い/長いリストの同じ窓で件数を比較する。
- 通常送り・途中再目標化・飛び・戻り・曲替え・サイズ変更で欠け/跳び/重なりなし。準備と完了の更新を除き、動作フレームのcompositions/measures/placements増分0。
- 目標値不変行の明暗ジョブ再起動0。単語なし待機の継続フレーム要求を増やさない。
- マスク・単語境界の描画が一致し、現在行/フェード行以外の重ねOffscreenが0。デバッグ詳細semanticsとreleaseの1ノードを維持。
- 初回一覧取得の重複0、復帰の全キャッシュ消去0、無線更新由来の一覧/画像取得0。表示経路のPM問い合わせと画像変換はメインスレッド外。
- packageイベント・非表示中更新・取得競合・失敗後再試行を検証し、設定の削除や古いデータの反映なし。
- 縮小済みreleaseで設定更新互換、起動、パネル中継、権限・歌詞・通信・画像を確認。APKサイズと起動/復帰時間を前後記録。

取得不能な項目は未測定と記す。欠け・見た目変更・設定消失・既存性能上限超過があれば修正して次のbetaで比較し、未測定の必須項目を合格にしない。

## 8. 範囲外

MediaWatcher のセッションごとの更新、SetRunner の履歴照会の非同期化、AppGraph の利用履歴集計頻度、ArtworkBackground の元サイズコピー、非表示時のタイマー停止は記録のみ。今回のコード変更対象に含めない。

## 9. 追加決定・未決

追加決定は窓のアンカー方式・D+Mの余白と保持寿命・窓内高さキャッシュ・デバッグ全行互換経路、目標値と即時世代による明暗更新、必要な重ね層のOffscreen維持、共有所有者の世代管理/失敗保持/非表示中receiver、revision分離、configの保守的keep、復帰3回比較。具体条件は各節のとおり。

未決は次版の正式名/beta名と版コード、panelhost縮小の採否、ベースラインプロファイル追加のユーザー承認と依存バージョン/生成環境、実測後の改善目標。実装API・最終keep規則は将来Taskの検証結果で確定する事項であり、現時点でAPI挙動やR8後の互換性を確認済みとはしない。

## ユーザーの決定(2026-11-04、未決の解消)
- 版は **2.2.0**。ベータ版は `2.2.0-betaN`(版コードは 38 から進める)。
- R8 は**本体(app)だけ**。中継アプリ(panelhost)はかけない。
- **ベースラインプロファイルを入れる**(新しいライブラリ `androidx.profileinstaller`、baselineprofile のプラグイン、macrobenchmark のモジュールの追加を承認。「新しいライブラリを入れない」の決まりの例外)。生成は司令塔が実機(adb)で行う。
- 目標は「どの計測値も v2.1.0 より悪くならない」こと。改善の量は記録し、体感で判断する。
- (2026-11-04 司令塔)「シークは即時配置」は、v1.7.1 以降の決まり「ちょうど1行進んだら送り、それ以外(2行以上の飛び・戻り・曲替え・最初の表示)はすぐ配置」の意味とする。シークを見分ける仕組みは足さない(隣の行へのシークは送りになる)。
