## 1. 目的と前提

### 1.1 目的
GT8D純正ランチャー（改造Launcher3）の使い勝手の不満を解消し、「左にアプリ・右にパネル」の形を保ったまま、**画面セットをワンアクションで切り替えられる車用ランチャー**を自作する。用途はほぼ動画と音楽。

### 1.2 純正ランチャーへの不満（解決対象）
1. 音楽ウィジェットが停止中に「再生していない」と表示されて見栄えが悪い
2. パネル最下段の2ボタン（分割・車）が場所を取っている → 右端バーに移したい
3. 右端バー最上段の時計が狭くて読めない（「10:3ξ」のように切れる）

### 1.3 ユーザーが決めた原則
- シンプルさ重視
- **走行中でも動作を変えない**（同乗者が見る前提。原則）
- 設定は **ランチャーの設定画面から** 行う（adb push で差し替えない）
- 子ども向けの過剰な制限は入れない
- **純正ホームの画面を、切り替えの途中で一瞬でも見せない**

### 1.4 確認済みの環境事実
| 項目 | 値 |
|---|---|
| OS | Android 15（API 35）、SoC SM6350（Lito） |
| 画面 | 1920x1080、238dpi（≒ 1291dp × 726dp）、大画面扱い |
| ナビゲーション | 3ボタン（`navigation_mode=0`）。画面端のスワイプはシステムの戻るジェスチャーと競合しない |
| 純正ランチャー | `com.android.launcher3/.uioverrides.QuickstepLauncher`（`/system/app/SdLauncher3`）。Recents 担当。Android 15 のアプリペア機能あり |
| 分割画面 | Android標準（WM Shell）。公式 API（`LAUNCH_ADJACENT`、アクセシビリティの `TOGGLE_SPLIT_SCREEN`、フリーフォーム + `setLaunchBounds`）では、自作アプリから分割を**作れない**（実験で確認） |
| メーカーの分割入口（E） | `com.sd.factoryconfig/.SplitActivity`（exported、ランチャー一覧には出ない）。extras `split_shortcur_package="左|右"`、`split_percent="1:1"/"2:3"/"3:2"/"3:7"/"7:3"`。本物の分割を比率つきで開く。第三者アプリから呼べる。**自作アプリを既定のホームにしたまま、再起動直後でも動く**。詳細 §5.3 |
| 独自アプリ | `com.suding.settings`、`com.sd.factoryconfig`（FactoryConfig、表示名「プラント設定」）、`com.carsyso.main`（MainAiBox）、`carnetos.usbmedia` |
| 独自設定の注意 | その他の設定 →「起動アプリケーション」＝ none のままにする（自作の起動処理と競合させない） |
| 開発時の接続 | PCモバイルホットスポット経由。端末は Windows 側のネットワークにあるため Windows の `adb.exe -s 192.168.137.248:5555` を使う。**再起動のたびに端末でワイヤレスデバッグの有効化が必要**。`scrcpy -s 192.168.137.248:5555 -b 16M --audio-source=playback` |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 画面セット | 左スロット＋右スロット＋比率の組み合わせ。番号順にループで切り替える |
| スロット | `アプリ`（任意のパッケージ）または `パネル`（右スロット専用） |
| ホーム（セット0） | 既定のホーム画面（自作）。左＝大きいアイコン一覧、右＝パネル |

| E | メーカーの分割入口で分割を開く方式（主） |
| D | 純正ホームのアプリペアをアクセシビリティでラベルから押す方式（退避策） |
| パネルのタスク | 分割の右側に置く自作アプリのタスク。パネル（と、その上に重ねる内蔵ブラウザ）を持つ |

## 4. 画面と操作

### 4.1 画面セット
- 構成：`左スロット（アプリ）` ＋ `右スロット（アプリ or パネル）` ＋ `比率`
- 並び：ホーム（セット0）→ セット1 → … → 最終セット → ホーム（ループ）
- 起動時：GT8D 起動（＝車のエンジンON）時に **最後に使っていたセット** を開く（§4.8）。ホームが最後ならホーム
- **比率**：設定画面では純正と同じ表記 **3:7・4:6・5:5・6:4・7:3**（左:右）で見せ、内部で E の文字列に変換する

  | 表示 | E の `split_percent` |
  |---|---|
  | 3:7 | `3:7` |
  | 4:6 | `2:3` |
  | 5:5 | `1:1` |
  | 6:4 | `3:2` |
  | 7:3 | `7:3` |

- **右がパネルのときは 4:6・5:5・6:4 のみ**（パネル側 40% 以上 ≒ 516dp 以上。3:7・7:3 ではパネルが約 387dp になり、72dp のボタンが窮屈になるため）

### 4.2 切り替え操作
| 操作 | 動作 | 有効な場面 |
|---|---|---|
| 左端の帯を内側へスワイプ | 次のセット | 常時 |
| 右端の帯を内側へスワイプ | 前のセット | 常時 |
| 左右どちらかの帯を長押し（既定1秒） | ホームへ | 常時 |
| 2本指で左右スワイプ | 次／前のセット | ランチャー画面（ホーム・パネル）表示中のみ。**おまけ扱い**（車経由でマルチタッチが届かない可能性があるため） |
| 右端バーの「ホーム」 | ホームへ | パネル表示中 |

- スワイプ帯は既定幅 8px、触れたときにうっすら光る演出（ON/OFF可）
- 分割中（パネルなし）は右端バーは表示しない。戻り方はスワイプ帯のみ

### 4.3 切り替えの幕
運転者は画面を一瞬しか見ないため、「操作が効いたことが即座に分かる」「次に何が出るかが先に分かる」「待ち時間が気にならない」を狙う。

- **即座の反応**：帯のジェスチャーを判定してから 100ms 以内に幕をフェードイン（120ms）。分割の起動は幕の表示と同時に始める（フェードの完了を待たない）
- **行き先の予告**：幕の中央に次のセットの**配置図**（左右のブロックを比率どおりに描き、アイコンとアプリ名を置く。パネルならパネルの図）。上にセット名（32sp 以上）、下に巡回の位置の点（●○○）。背景はパネルと同じ壁紙を暗めにしたもの。ぼかし等の重い効果は使わない
- **待ち時間**：0.8 秒を超えたら、配置図の下に細いライム色（`Palette.Accent`）の進行線を出す。0.8 秒未満では出さない（ちらつき防止）
- **幕を外す合図**：左右の両方のパッケージが前面化したこと（`ForegroundWatcher`、§5.5）。右がパネルなら、パネルの分割内での `onResume` も合図にする。合図が得られないときは時間で外す（暖かい起動 0.8 秒、冷えた起動 3.5 秒）。外すときは 150ms でフェードアウト
- **暖かい／冷えた起動の見分け方**：他アプリのタスクの有無は自作アプリから見えないため、自作アプリのプロセスが「起動してから、そのパッケージを前面化させた（または前面化を見た）か」の記録で判定する（`SetRunner`・パネルからの起動、`ForegroundWatcher` が見た前面化）。左右の両方に記録があれば暖かい起動、どちらかに無ければ冷えた起動。自作のパッケージ（パネル）は、自分のタスク（`ActivityManager.appTasks`）があれば暖かい起動とする。**見分けられないときは冷えた起動（3.5 秒）に寄せる**。いずれも 4 秒の安全タイマーが上限
- **安全タイマー（必須）**：幕は、**最初の呼び出しから合計 4 秒で必ず外れる**。`ForegroundWatcher` の結果と無関係の独立したタイマー。`EdgeStripService` の停止・例外の場合も必ず外す（`finally` 相当）。4 秒で外れたら失敗として記録する。4 秒の根拠：冷えた起動の実測が約 2.5〜3 秒
- **呼び直し**：3 秒の時点で両側がそろわず、**しかも E が何も動かした形跡が無い**ときだけ、1回だけ呼び直す。形跡とは、呼び出しの後に、左右どちらかのアプリ・純正ランチャー（E の冷えた起動の途中で出る既定のホーム）の前面化、または自作のパネル・ホームの再開（分割の内外を問わない）があったこと。形跡があれば、E の処理は途中なので呼び直さず、4 秒の安全タイマーに任せる。呼び直しで幕を延長しない（残り時間があれば幕の下で、なければ幕なしで裏で行う）。2026-10-30 変更：冷えた起動の E は 3 秒を少し超えることがあり（実測 3.3〜3.6 秒）、途中で呼び直すとシステムが分割を解き、パネルが分割から外れたため
- **連続スワイプ**：幕の表示中のスワイプは行き先を更新する（配置図が切り替わる）。起動は実行中のものが終わってから、最後の行き先だけを実行する
- **操作の安全**：幕は下の画面へのタッチを遮る。左右の帯は幕より上に置き、スワイプ・長押しは効く
- **失敗表示**：失敗したら幕を外し、上部に短く「切り替えに失敗しました」
- ホーム（セット0）へ戻るときも同じ幕を短く出す（見え方の一貫性）
- 適用範囲：起動後の切り替え（帯・ドック・2本指・パネルの「分割」保存後）。**起動時は §4.8 の起動画面を使い、幕は使わない**

### 4.4 ホーム画面（セット0）
- 左：大きいアイコン一覧（設定で選んだアプリ・順番）
- 右：パネル

### 4.5 パネル
上から：
1. **メディアカード**
   - 停止中：「停止中アプリ」（既定 Apple Music）のアイコン＋大きいデジタル時計。アイコンタップでそのアプリを起動
   - 再生中：ミニプレイヤー（ジャケット、曲名、アーティスト、進行バー＋経過／残り時間、戻る／再生・一時停止／送る、☆はアプリがカスタムアクションとして公開している場合のみ）。進行バーでシーク可
   - 対象アプリの決め方：状態が「再生中」のセッションを優先、なければ最後に再生していたセッション、どちらも無ければ停止中表示
   - ☆の識別子：Apple Music は `com.apple.android.music.playback.action.FAVORITE`（実験④で確認）
   - デザインは Apple Music の再生画面の並びを参考にするが、Apple のアイコン素材は使わない
2. **アイコン一覧**（2行×3列。最後のマスは「＋」→ 設定の該当箇所へ）
   - **パネルが分割の右にいるとき**：アイコンを押すと `NEW_TASK | LAUNCH_ADJACENT | MULTIPLE_TASK` で**左側だけを入れ替える**。パネルは右に残る（実験 D-3 で確認）。幕は出さない（ランチャーを経由しない直接の起動でちらつかないため）
   - **パネルがホームの右にいるとき**：普通に全画面で開く
3. **右端バー**（縦。上から）
   1. ステータス（Wi-Fi・Bluetooth のアイコンのみ）
   2. よく使うアプリ（最大4）
   3. ホーム
   4. 分割（＝画面セットの新規作成画面を開く。保存するとセットに追加され、そのまま開く）
   5. 車（純正画面に戻る。§10.2 実験⑧で仕組みが確定するまで非表示）
   6. アプリ一覧（全アプリ。**長押しで設定画面**）
- 縦に収まらない場合は、右端バーとアイコン一覧の列をスクロールできるようにする（内容を切り捨てない）

### 4.6 アプリ一覧
- 起動可能な全アプリを表示
- **「純正ランチャー」（Launcher3）を必ず含める**（安全装置。§7.2）
- 自作アプリの「GT8D パネル」（§5.2 PanelActivity）は一覧から除外する

### 4.7 内蔵ブラウザ（URL 受け口）
- 既定のブラウザ（RoleManager の ROLE_BROWSER）として http/https の VIEW を受ける
- E にはパッケージ名しか渡せないため、**分割の右側の自作アプリは「パネルのタスク」1つにまとめ、分割の右に出すブラウザは PanelActivity の画面の中に表示する**（別の Activity にしない。「閉じる」や戻りきった「戻る」でパネルの表示に戻る）。2026-10-30 変更：別の Activity を重ねる方式では、冷えた起動で E の遷移中に開いたブラウザが分割から外れ、全画面になったため
- **全画面で開くブラウザは、パネルのタスクに重ねず別のタスクで開く**（全画面用の別名の Activity、別の `taskAffinity`）。「戻る」で閉じると、下にあるホームや元のアプリにそのまま戻る（パネルが分割の外で出てくる経路をなくす）
- **前面の判定方法**：手がかりは ①自作の HomeActivity・PanelActivity の再開状態と `isInMultiWindowMode`、②`SetRunner` が最後に開いたセットの記録（左右のパッケージ）、③`ForegroundWatcher` の直近の前面化イベント、④リンクを送ってきたアプリ（`BrowserActivity` の `referrer`）。判定の順：
  1. ホームが再開中 → 「ホーム」
  2. パネルが分割の中で再開中 → 「アプリ ｜ パネル」
  3. 最後に開いたセットが「アプリ ｜ アプリ」で、その後に別のアプリの前面化が無く、送り元がその左右のどちらか → 「アプリ ｜ アプリ」
  4. 送り元が分かる → その送り元を X として「全画面アプリ X」
  5. **分からない → 内蔵ブラウザを全画面で開く**（誤って分割を崩すより安全なため）
- 開き方（設定で選択）：
  - 既定：内蔵ブラウザで分割
    - 前面がホームのとき：内蔵ブラウザを全画面で開く
    - 前面が全画面アプリ X のとき：E で「X ｜ 自作」を開き、パネルの画面の中にブラウザを表示する（右にブラウザ）
    - 前面が「アプリ ｜ パネル」の分割のとき：パネルの画面の中にブラウザを表示する（右だけ入れ替わる）
    - 前面が「アプリ ｜ アプリ」の分割のとき：E で「左のアプリ ｜ 自作」にして、右をブラウザにする
  - Chrome で開く
- 内蔵ブラウザに「Chromeで開き直す」ボタンを常設
- 次のドメインは自動で Chrome に回す：`accounts.google.com`（WebView では Google ログインが拒否されるため）。リストは設定データに持つ
- YouTube などアプリリンクを持つ URL は Android が直接アプリを開くので、内蔵ブラウザでは扱わない

### 4.8 起動時（エンジンON）の扱い
起動直後は、左右とも必ず冷えた起動になり、システムも混み合う。帯のサービスも動いていない場合がある。タッチを遮る幕を長く出すのは危険なので、**幕を使わない別の扱い**にする。

1. 自作の HomeActivity（既定のホーム）が最初に出る。ホームの上に**起動画面**を出す（普通の画面で、タッチを遮らない）：「3 秒後に前回のセットを開きます」のカウントダウン、行き先の配置図、「今すぐ開く」「ホームのまま使う」ボタン
2. カウントダウン中に「ホームのまま使う」が押されたら、E を呼ばない
3. E を呼んだあとに「ホームのまま使う」が押されたら、取り消しとして記録し、**分割が出てきた時点（前面化の検知）、または上限 10 秒でホームに戻す**。失敗として数えない
4. 起動画面の上限は **10 秒**。過ぎたらホームのまま止まり、失敗として記録する。**起動時の時間切れは E の連続失敗に数えない**（「入口が無い」「呼び出しで例外」だけは数える）
5. 冷えた起動の途中で一瞬出る「既定のホーム」のステップは自作のホーム（起動画面）なので、純正ホームは映らない（実験 H2 で確認）
6. 設定「**車との接続を待ってから前回のセットを開く**」を用意する。既定値と、接続の検知方法（候補：ディスプレイの構成変更イベント、メーカー SDK の `SmartBoxCarPlayManager`）は納車後の実験⑩⑪で決める
7. `SafetyGuard` の退避中は、起動時の自動処理を行わない

## 5. 技術構成

### 5.1 技術スタック
- Kotlin ＋ Jetpack Compose、minSdk 35 / targetSdk 35
- 単一アプリ `com.gt8d.launcher`
- 設定保存：DataStore ＋ kotlinx.serialization（JSON 1ファイル）

### 5.2 部品
| 部品 | 役割 | 主なAndroid機能 |
|---|---|---|
| ConfigRepository | 設定の読み書き、既定値、デフォルトに戻す、**v1→v2 の移行** | DataStore |
| SetRunner | セットを開く。比率を E の文字列に変換し `SplitLauncher` を呼ぶ。幕の表示と完了待ち。連続スワイプのまとめ。最後のセットを記録 | — |
| SplitLauncher（インターフェース） | 「左・右・比率で分割を開く」の抽象。実装は `VendorSplitLauncher`（E）と `AppPairSplitLauncher`（D） | — |

| PanelActivity | **自作アプリのランチャー用の入口**（MAIN/LAUNCHER、表示名「GT8D パネル」）。分割の右側。**分割の外（`isInMultiWindowMode == false`）にいるときの転送**：起動直後には判定しない。`SetRunner` の「分割を開いている最中」の印（同じプロセス内の共有状態、開始時刻つき）があるあいだは転送しない。印が消えた（完了または 4 秒の安全タイマー）あとも分割の外なら HomeActivity へ転送して閉じる。印が無いときに分割の外で開かれたら、1.5 秒待って分割に入らなければ転送する（冷えた起動では E がパネルをいったん全画面で起動するため。§5.3） | resizeable、`onMultiWindowModeChanged` |

| LinkRouter | URL の振り分け（§4.7） | — |

### 5.3 分割の開き方（E が主、D が退避策）

**E：メーカーの分割入口**
```
Intent().setComponent(ComponentName("com.sd.factoryconfig", "com.sd.factoryconfig.SplitActivity"))
  .putExtra("split_shortcur_package", "<左パッケージ>|<右パッケージ>")   // 綴りは原文のまま
  .putExtra("split_percent", "3:2")                                    // §4.1 の対応表
  .addFlags(FLAG_ACTIVITY_NEW_TASK)
```
- 仕組み：`SplitActivity` が `persist.splitscreen.percent` に比率を書き、ブロードキャスト `com.android.intent.ext.main.split.two.screen` を送る。純正ランチャーのプロセス（Recents 担当として常駐）が受けて、SystemUI の Shell で分割を開く
- 右がパネルのときは、右に自作のパッケージ名 `com.gt8d.launcher` を渡す（ランチャー用の入口 = PanelActivity が開く）
- 実験で確認済み：本物の分割（タイトルバーなし）、比率どおり、第三者アプリから呼べる、分割中から別の組み合わせへの切り替え、冷えた起動でも右側が空にならない、既定のホームが自作でも動く（再起動直後も）
- 画面の流れ：両方のアプリのタスクが既にあれば、暗い無地の画面（`SplitActivity` 自身）が約 0.5 秒出るだけ。**タスクがまだ無いアプリを含むときは**、そのアプリの全画面 → 既定のホーム（自作）→ 分割、の順で約 2.5 秒かかる。どちらも幕（§4.3）で隠す
- 依存：メーカーアプリ（非公開の入口）。OS・ファームの更新で変わりうるため、`VendorBridge` で検出し、使えなければ退避する

**D：純正のアプリペアをアクセシビリティで押す（退避策）**
- 純正ホームの中央のアイコン一覧に置いたアプリペア（ラベル「左アプリ名|右アプリ名」）を、`AppPairService` が HOME → ラベルで探して `ACTION_CLICK`。本物の分割（ペアに保存した比率）で開く
- 自作パネルも、純正の分割で「GT8D パネル」を選べばペアにできる
- 前提：アクセシビリティの許可、純正ホームの**表示中のページ**にペアがある、各アプリが起動済み（冷えた起動では右側が空になることがある）
- D は HOME を経由するため純正ホームが映る。幕で隠す
- D を使うときは、既定のホームを純正にする必要は無い（HOME の代わりに純正ランチャーを明示起動して押す。実装時に確認）

**Launcher3 は Recents 担当として残す。無効化・削除しない**（E の受け口も純正ランチャーのプロセスにある）

### 5.4 データモデル（概略、設定 version 2）
```kotlin
@Serializable data class LauncherConfig(
  val version: Int = 2,
  val screenSets: List<ScreenSet>,          // セット1以降（ホームは暗黙のセット0）
  val homeApps: List<String>,               // パッケージ名
  val panelApps: List<String>,              // 最大5（6マス目は「＋」）
  val dockApps: List<String>,               // 最大4
  val idleApp: String,                      // 停止中表示アプリ
  val link: LinkConfig,
  val gesture: GestureConfig,
  val boot: BootConfig = BootConfig(),
)
@Serializable data class ScreenSet(
  val id: String,
  val left: Slot.App,
  val right: Slot,
  val ratio: SplitRatio = SplitRatio.R5_5,  // 右が Panel なら R4_6 / R5_5 / R6_4 のみ
  val appPairLabel: String? = null,         // D 用（純正ホームのペアのラベル）
)
enum class SplitRatio(val label: String, val vendorValue: String) {
  R3_7("3:7","3:7"), R4_6("4:6","2:3"), R5_5("5:5","1:1"), R6_4("6:4","3:2"), R7_3("7:3","7:3")
}
@Serializable sealed interface Slot {
  @Serializable data class App(val pkg: String) : Slot
  @Serializable data object Panel : Slot
}
@Serializable data class LinkConfig(val mode: LinkMode = LinkMode.InAppSplit, val chromeDomains: List<String> = listOf("accounts.google.com"))
enum class LinkMode { InAppSplit, Chrome }
@Serializable data class GestureConfig(val stripWidthPx: Int = 8, val glow: Boolean = true, val longPressMs: Int = 1000)
@Serializable data class BootConfig(val waitForCar: Boolean = false)   // 既定値は実験⑩⑪で確定
```
- **読み込みの規則**：`version` が**今の version より新しい、または壊れている**ときだけ既定値に戻し、`config.bak.json` に退避する。**古い version（v1）は移行する**（`ratio` は `R5_5`、`appPairLabel` は null、`boot` は既定値で埋める）。v1 は壊れた扱いにせず、退避ファイルも作らない
- 最後に使ったセット番号は設定データとは別に保存（「デフォルトに戻す」の対象外）
- `SplitModeState`（現在の方式、連続失敗回数、最後の失敗理由）も設定とは別に保存（「デフォルトに戻す」の対象外）

### 5.5 前面化の検知（ForegroundWatcher）
- 手段：**使用状況へのアクセス**（`UsageStatsManager.queryEvents` の `ACTIVITY_RESUMED`）。アクセシビリティは使わない
- 用途：幕を外す合図、片側欠けの検知（冷えた起動の確認と1回の呼び直し）
- 分割中は2つのアプリが同時に再開状態になるため、両方のイベントが届く想定。**この端末での届き方は未確認**のため、実装の最初の検証項目にする（§10.3）
- 使えない場合（許可なし、イベントが届かない）：幕は時間で外す。片側の欠けは検知できないので呼び直さない。失敗の判定は「入口が無い／呼び出しで例外」だけになる（§7.1）。この制約を許可のチェックに表示する

## 6. 設定画面

開き方：右端バー「アプリ一覧」の長押し。

1. **画面セット**：一覧、並べ替え（▲▼ のボタン。車の画面でドラッグは扱いにくいため）、追加・編集・削除。編集＝左スロット（アプリ）／右スロット（アプリ or パネル）／**比率**（3:7・4:6・5:5・6:4・7:3。右がパネルなら 4:6・5:5・6:4）。分割非対応アプリ（`RESIZE_MODE_UNRESIZEABLE`）を選んだら警告
2. **パネルとホーム**：ホームのアイコン一覧、パネルのアイコン一覧、右端バーのよく使うアプリ（最大4）、停止中表示アプリ
3. **リンクの行き先**：内蔵ブラウザで分割（既定）／Chrome。Chromeに回すドメインの一覧
4. **操作**：スワイプ帯の幅、光る演出 ON/OFF、長押し時間
5. **起動時**：「車との接続を待ってから前回のセットを開く」
6. **許可のチェック**：既定のホーム／通知へのアクセス／他のアプリの上に表示／既定のブラウザ／Bluetooth 接続（状態表示用）／**使用状況へのアクセス**／（D のときのみ）**アクセシビリティ**。未許可は Android の該当設定画面へ1タップで遷移。あわせて**分割の方式の状態**を表示（「メーカー方式で動作中」／「分割が使えなくなりました」／「予備方式で動作中」）と、「メーカー方式に戻す」ボタン
7. **予備方式（D）の準備**：E が使えないときに表示。①アクセシビリティの許可、②純正ホームでのペアの作り方の案内、③「ペアを走査する」ボタン（純正ホームの表示中のページからペアのラベルを読み取り、一覧から各セットに割り当てる）。準備が揃ったら自動で D に移る
8. **純正ランチャーに戻す**：既定のホーム選択画面を開く
9. **デフォルトに戻す**：確認ダイアログ → 1〜5 を §8 の既定値に初期化（6〜7 の許可・方式の状態、最後に使ったセットは対象外）
10. **安全モードを解除**：SafetyGuard の退避を解除（§7.2）

## 7. エラー処理と安全装置

### 7.1 エラー時の動き
| 状況 | 動き |
|---|---|
| セットのアプリが未インストール | スロットに「アプリが見つかりません」表示 |
| 分割非対応のアプリ | 左アプリのみ全画面で開き、短いメッセージ |
| 許可不足 | パネルに小さく「許可が必要」→ 設定⑥へ |
| EdgeStripService 停止 | HomeActivity / PanelActivity の onResume で再開 |
| 既定値に未インストールのアプリ | 飛ばす |
| E の入口が無い（`resolveActivity` が null） | 失敗として記録。E を「使えない」扱いにし、下の「E が使えないとき」へ |
| E の呼び出しで例外 | 失敗として記録 |
| 幕の 4 秒以内に左右の両方が前面化しない（ForegroundWatcher が使えるとき） | E が何も動かした形跡が無ければ、3 秒の時点で1回だけ呼び直し（幕は延長しない。§4.3）。駄目なら失敗として記録 |
| 幕の安全タイマー（4 秒）で外れた | 失敗として記録 |
| 連続 3 回の失敗（**判定できた失敗だけ数える**） | E を「使えない」扱いにする |
| **E が使えないとき** | パネルに「分割が使えなくなりました」を表示し、セットは**左のアプリだけ全画面**で開く。**D は、アクセシビリティが ON かつ全セットのペアが走査で見つかっているときだけ自動で使う**。設定⑦で D を準備できる |
| **E の自動復帰** | 設定⑥「メーカー方式に戻す」で手動で戻せる。加えて、**起動時に E の入口が見つかれば（`resolveActivity` 成功）、自動で E に戻し、連続失敗の回数を 0 に戻す**（使用状況イベントの遅延などによる誤判定で止まっても、エンジンをかけ直せば復活する） |
| D でアクセシビリティが OFF | パネルに「許可が必要」→ 1タップで設定へ。セットは左だけ全画面 |
| D でペアのラベルが見つからない | 失敗として記録し、左だけ全画面。設定⑦に「ペアを走査し直す」を出す |
| ForegroundWatcher が使えない | 失敗の判定は「入口が無い／呼び出しで例外」だけ。片側の欠けは検知できないので呼び直さない。幕は時間で外す。許可のチェックに表示 |
| 起動時の時間切れ（10 秒） | ホームのまま止まり、記録する。E の連続失敗に数えない |
| 起動時の「ホームのまま使う」の取り消し | 記録のみ。失敗に数えない |
| 分割中に画面の解像度が変わった | （候補）同じセットで E を呼び直して配置を整え直す。採否は実験⑩で決める |

### 7.2 安全装置（GT8D 本体にタッチが無く、車の画面が唯一の入力のため必須）
- アプリ一覧に常に「純正ランチャー」を表示
- 設定に「純正ランチャーに戻す」
- **SafetyGuard**：起動後10秒以内のクラッシュが3回連続したら、次回起動時は何もせず `com.android.launcher3/.uioverrides.QuickstepLauncher` を明示起動し、自作の自動処理（最後のセットを開く、方式の自動切り替え等）を停止。設定画面から解除
- **幕の安全タイマー**：起動後の切り替えの幕は、何があっても最大 4 秒で外れる（§4.3）
- **起動時は幕を使わない**：タッチを遮らない起動画面、3 秒のカウントダウン、上限 10 秒（§4.8）

## 12. テスト

- **自動テスト（JVM）**
  - 設定：シリアライズ／読み込み、デフォルトに戻す、**v1→v2 の移行（設定が残り比率が補われる）、v1 は壊れた扱いにしない、v3 は壊れた扱い**
  - 比率：表示（4:6 など）→ E の文字列の5通り、右がパネルなら 4:6・5:5・6:4 だけ
  - 巡回（次／前のループ）、メディア状態の変換、対象セッション選択、SafetyGuard のカウント判定
  - `SplitModeSelector`：連続 3 回で E を使えない扱い、判定できない失敗は数えない、D の準備が無ければ D に切り替えず「左だけ全画面」、起動時の時間切れ・取り消しは数えない、起動時に入口があれば E に自動復帰し回数を 0 に
  - 幕：前面化の通知が来なくても 4 秒で必ず外れる（テスト用の時計）、呼び直しで延長しない
  - `SetRunner`：連続スワイプで行き先が更新され、起動は最後の行き先だけ
  - 起動画面：3 秒以内の「ホームのまま使う」で E を呼ばない、呼んだあとの取り消しで分割が出たらホームに戻す
  - `PanelActivity`：「分割を開いている最中」の印があるあいだは転送しない。印が消えても分割の外ならホームへ転送。印が無ければ 1.5 秒待って分割に入らないときだけ転送
  - 暖かい／冷えた起動の見分け：記録が両方あれば暖かい、片方でも無ければ冷えた、見分けられなければ冷えた
  - リンクの前面判定：判定の5段階（ホーム／アプリ｜パネル／アプリ｜アプリ／全画面 X／不明→全画面ブラウザ）
  - ブラウザの戻り方：全画面のブラウザから戻るとホーム（別タスクなのでパネルを経由しない）。分割の右のブラウザから戻るとパネル（転送されない）
- **実機確認（GT8D、adb＋scrcpy）**：§4 の各操作、§7 のエラー時の動き、§10.3 の実験、幕の見え方・冷えた起動・連続スワイプ・取り消しをチェックリストで確認。純正ホームが映らないことは `screenrecord --output-format=raw-frames` のコマ送りで確認できる
- 車での確認は納車後に §10.2 として実施
