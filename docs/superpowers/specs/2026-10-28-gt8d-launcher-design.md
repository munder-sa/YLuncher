# GT8D カスタムランチャー 設計仕様書

- 作成日：2026-10-28
- 対象：Linkifun GT8D（車載AI Box）→ 新型RAV4 GR SPORT（有線CarPlay）
- 実装体制：Claude Code（設計・指揮・レビュー）＋ Antigravity（実装）
- ステータス：設計承認済み → 実装計画（writing-plans）待ち

---

## 1. 目的と前提

### 1.1 目的
GT8D純正ランチャー（改造Launcher3）の使い勝手の不満を解消し、「左にアプリ・右にパネル」の形を保ったまま、**画面セットをワンアクションで切り替えられる車用ランチャー**を自作する。用途はほぼ動画と音楽。

### 1.2 純正ランチャーへの不満（解決対象）
1. 音楽ウィジェットが停止中に「再生していない」と表示されて見栄えが悪い
2. パネル最下段の2ボタン（分割・車）が場所を取っている → 右端バーに移したい
3. 右端バー最上段の時計が狭くて読めない（「10:3ξ」のように切れる）

### 1.3 ユーザーが決めた原則
- シンプルさ重視
- **走行中でも動作を変えない**（同乗者が見る前提。原則）
- 設定は **ランチャーの設定画面から** 行う（adb push で差し替えない）
- 子ども向けの過剰な制限は入れない

### 1.4 確認済みの環境事実
| 項目 | 値 |
|---|---|
| OS | Android 15（API 35）、SoC SM6350（Lito） |
| 画面 | 1920x1080、238dpi、sw726dp（大画面扱い） |
| 純正ランチャー | `com.android.launcher3/.uioverrides.QuickstepLauncher`（Recents担当。Android 15 のアプリペア機能で分割ショートカットを作成） |
| 分割画面 | Android標準（WM Shell）。純正は左60:右40、区切り15px。比率は純正専用のShell APIで指定しており、外部から呼べる入口は無い |
| 独自アプリ | `com.suding.settings`、`com.sd.factoryconfig`、`com.carsyso.main`、`carnetos.usbmedia` |
| 独自設定の注意 | その他の設定 →「起動アプリケーション」＝ none のままにする（自作の起動処理と競合させない） |
| 開発時の接続 | PCモバイルホットスポット経由 `adb connect 192.168.137.248:5555`、`scrcpy -s 192.168.137.248:5555 -b 16M --audio-source=playback` |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 画面セット | 左スロット＋右スロットの組み合わせ。番号順にループで切り替える |
| スロット | `アプリ`（任意のパッケージ）または `パネル`（右スロット専用） |
| ホーム（セット0） | 既定のホーム画面。左＝大きいアイコン一覧、右＝パネル |
| パネル | メディアカード＋アイコン一覧＋右端バーをまとめた画面 |

## 4. 画面と操作

### 4.1 画面セット
- 構成：`左スロット（アプリ）` ＋ `右スロット（アプリ or パネル）`
- 並び：ホーム（セット0）→ セット1 → … → 最終セット → ホーム（ループ）
- 起動時：GT8D 起動（＝車のエンジンON）時に **最後に使っていたセット** を開く。ホームが最後ならホーム
- 比率：システム任せ（50:50 または前回の比率）。ユーザーが分割のつまみで調整

### 4.2 切り替え操作
| 操作 | 動作 | 有効な場面 |
|---|---|---|
| 左端の帯を内側へスワイプ | 次のセット | 常時 |
| 右端の帯を内側へスワイプ | 前のセット | 常時 |
| 左右どちらかの帯を長押し（既定1秒） | ホームへ | 常時 |
| 2本指で左右スワイプ | 次／前のセット | ランチャー画面（ホーム・パネル）表示中のみ。**おまけ扱い**（車経由でマルチタッチが届かない可能性があるため） |
| 右端バーの「ホーム」 | ホームへ | パネル表示中 |

- スワイプ帯は既定幅 8px、触れたときにうっすら光る演出（ON/OFF可）
- 分割中（パネルなし）は右端バーは表示しない。戻り方はスワイプ帯のみ

### 4.3 ホーム画面（セット0）
- 左：大きいアイコン一覧（設定で選んだアプリ・順番）
- 右：パネル

### 4.4 パネル
上から：
1. **メディアカード**
   - 停止中：「停止中アプリ」（既定 Apple Music）のアイコン＋大きいデジタル時計。アイコンタップでそのアプリを起動
   - 再生中：ミニプレイヤー（ジャケット、曲名、アーティスト、進行バー＋経過／残り時間、戻る／再生・一時停止／送る、☆はアプリがカスタムアクションとして公開している場合のみ）。進行バーでシーク可
   - 対象アプリの決め方：状態が「再生中」のセッションを優先、なければ最後に再生していたセッション、どちらも無ければ停止中表示
   - デザインは Apple Music の再生画面の並びを参考にするが、Apple のアイコン素材は使わない
2. **アイコン一覧**（2行×3列。最後のマスは「＋」→ 設定の該当箇所へ）
3. **右端バー**（縦。上から）
   1. ステータス（Wi-Fi・Bluetooth のアイコンのみ）
   2. よく使うアプリ（最大4）
   3. ホーム
   4. 分割（＝画面セットの新規作成画面を開く。保存するとセットに追加され、そのまま開く）
   5. 車（純正画面に戻る。§9 実験⑧で仕組みが見つからなければ非表示）
   6. アプリ一覧（全アプリ。**長押しで設定画面**）

### 4.5 アプリ一覧
- 起動可能な全アプリを表示
- **「純正ランチャー」（Launcher3）を必ず含める**（安全装置。§7.2）

### 4.6 内蔵ブラウザ（URL 受け口）
- 既定のブラウザ（RoleManager の ROLE_BROWSER）として http/https の VIEW を受ける
- 開き方（設定で選択）：
  - 既定：内蔵ブラウザで、今前面にあるアプリの隣に分割で開く
    - 前面がホームのとき：内蔵ブラウザを全画面で開く（ホームは分割に入れられないため）
    - 前面が全画面アプリのとき：そのアプリの隣に開く
    - 既に分割中のとき：右側を内蔵ブラウザに置き換える（実験⑥の結果、右側を狙えない場合は「前面でない側」）
  - Chrome で開く
- 内蔵ブラウザに「Chromeで開き直す」ボタンを常設
- 次のドメインは自動で Chrome に回す：`accounts.google.com`（WebView では Google ログインが拒否されるため）。リストは設定データに持つ
- YouTube などアプリリンクを持つ URL は Android が直接アプリを開くので、内蔵ブラウザでは扱わない

## 5. 技術構成

### 5.1 技術スタック
- Kotlin ＋ Jetpack Compose、minSdk 35 / targetSdk 35
- 単一アプリ（パッケージ名は実装計画で確定。仮 `com.gt8d.launcher`）
- 設定保存：DataStore ＋ kotlinx.serialization（JSON 1ファイル）

### 5.2 部品
| 部品 | 役割 | 主なAndroid機能 |
|---|---|---|
| ConfigRepository | 設定の読み書き、既定値の保持、デフォルトに戻す | DataStore |
| SetRunner | セットを開く。次／前の計算（ループ）。最後のセットを記録 | Activity 起動、`FLAG_ACTIVITY_LAUNCH_ADJACENT` |
| HomeActivity | 既定のホーム（左アイコン一覧＋右パネル） | `category.HOME` |
| PanelActivity | 分割の右側に置ける通常 Activity。中身はパネル Composable | `activityType=standard`、resizeable |
| PanelContent | メディアカード・アイコン一覧・右端バーの Composable。**どの幅でも崩れない**（3:7〜7:3相当、および車接続時の解像度） | Compose レスポンシブレイアウト |
| MediaWatcher | 再生セッションの監視と操作 | NotificationListenerService、MediaSessionManager、MediaController |
| EdgeStripService | 左右の帯を常駐。スワイプ・長押し・光る演出 | フォアグラウンドサービス（specialUse）、`TYPE_APPLICATION_OVERLAY` |
| BrowserActivity | URL受け口・内蔵ブラウザ | WebView、ROLE_BROWSER |
| CarHomeAction | 純正画面に戻る | 実験⑧の結果で実装（不明なら非表示） |
| SettingsActivity | 設定画面 §6 | Compose |
| SafetyGuard | 連続クラッシュ検知と純正ランチャーへの退避 | Application.onCreate 先頭 |
| BootReceiver | 起動時に EdgeStripService 開始 | `BOOT_COMPLETED` |
| DiagLog | 車での不具合追跡用ログ（logcat タグ＋アプリ内リングバッファ） | — |

### 5.3 分割の開き方（前提と制約）
- 純正ランチャーは Recents 担当専用の Shell API で比率つき分割を起動しているが、自作アプリからは使えない（外部入口なしを確認済み）
- 自作では「左アプリを起動 → 右（アプリ or PanelActivity）を `FLAG_ACTIVITY_LAUNCH_ADJACENT | FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_MULTIPLE_TASK` で起動」する
- 左右どちらに出るか、分割中からの切り替え挙動、比率は **実験①⑤⑥で確認**し、結果を実装計画に反映する
- Launcher3 は Recents 担当として残す。**無効化・削除しない**

### 5.4 データモデル（概略）
```kotlin
@Serializable data class LauncherConfig(
  val version: Int = 1,
  val screenSets: List<ScreenSet>,          // セット1以降（ホームは暗黙のセット0）
  val homeApps: List<String>,               // パッケージ名
  val panelApps: List<String>,              // 最大5（6マス目は「＋」）
  val dockApps: List<String>,               // 最大4
  val idleApp: String,                      // 停止中表示アプリ
  val link: LinkConfig,
  val gesture: GestureConfig,
)
@Serializable data class ScreenSet(val id: String, val left: Slot.App, val right: Slot)
@Serializable sealed interface Slot {
  @Serializable data class App(val pkg: String) : Slot
  @Serializable data object Panel : Slot
}
@Serializable data class LinkConfig(val mode: LinkMode = LinkMode.InAppSplit, val chromeDomains: List<String> = listOf("accounts.google.com"))
enum class LinkMode { InAppSplit, Chrome }
@Serializable data class GestureConfig(val stripWidthPx: Int = 8, val glow: Boolean = true, val longPressMs: Int = 1000)
```
- 最後に使ったセット番号は設定データとは別に保存（「デフォルトに戻す」の対象外）

## 6. 設定画面

開き方：右端バー「アプリ一覧」の長押し。

1. **画面セット**：一覧、ドラッグ並べ替え、追加・編集・削除。編集＝左スロット（アプリ）／右スロット（アプリ or パネル）。分割非対応アプリを選んだら警告
2. **パネルとホーム**：ホームのアイコン一覧、パネルのアイコン一覧、右端バーのよく使うアプリ（最大4）、停止中表示アプリ
3. **リンクの行き先**：内蔵ブラウザで分割（既定）／Chrome。Chromeに回すドメインの一覧
4. **操作**：スワイプ帯の幅、光る演出 ON/OFF、長押し時間
5. **許可のチェック**：既定のホーム／通知へのアクセス／他のアプリの上に表示／既定のブラウザ／Bluetooth 接続（状態表示用）。未許可は Android の該当設定画面へ1タップで遷移
6. **純正ランチャーに戻す**：既定のホーム選択画面を開く
7. **デフォルトに戻す**：確認ダイアログ → 1〜4 を §8 の既定値に初期化（5 の許可、最後に使ったセットは対象外）

## 7. エラー処理と安全装置

### 7.1 エラー時の動き
| 状況 | 動き |
|---|---|
| セットのアプリが未インストール | スロットに「アプリが見つかりません」表示 |
| 分割で開けない（アプリ非対応など） | 左アプリのみ全画面で開き、短いメッセージ |
| 許可不足 | パネルに小さく「許可が必要」→ 設定⑤へ |
| EdgeStripService 停止 | HomeActivity / PanelActivity の onResume で再開 |
| 既定値に未インストールのアプリ | 飛ばす |

### 7.2 安全装置（GT8D 本体にタッチが無く、車の画面が唯一の入力のため必須）
- アプリ一覧に常に「純正ランチャー」を表示
- 設定に「純正ランチャーに戻す」
- **SafetyGuard**：起動後10秒以内のクラッシュが3回連続したら、次回起動時は何もせず `com.android.launcher3/.uioverrides.QuickstepLauncher` を明示起動し、自作の自動処理（最後のセットを開く等）を停止。設定画面から解除

## 9. 見た目のルール

- **ダーク固定**（背景は黒系、パネルは濃いグレー）
- タッチ領域は最小 **72dp 角**
- 文字は本文 **20sp 以上**、時計は特大
- アプリアイコンは各アプリ本来のものを使用
- 重いエフェクト（リアルタイムぼかし等）は使わない（SM6350 の負荷を考慮）

### 9.1 素材

**Muse に作ってもらうもの**（元データは `design/assets/`、実装担当が `app/src/main/res/` に変換）
| 素材 | 使う場所 | 形式 |
|---|---|---|
| ランチャーのアプリアイコン | アプリ一覧・設定 | アダプティブアイコン（前景・背景・モノクロ）、SVG |
| ジャケットが無いときの代替画像 | ミニプレイヤー | SVG、または正方形 PNG 1024px |
| ホームの壁紙（ダーク） | ホーム・パネルの背景 | PNG 1920x1080。他の解像度・比率でも主要部分が切れない構図 |

Muse への共通ルール：ダーク背景で映える色づかい。

**標準アイコンを使うもの**（Material Symbols）
- 右端バーのボタン（ホーム・分割・車・アプリ一覧）
- 再生・一時停止・戻る・送る・☆
- 設定画面のアイコン

**コードで描くもの**
- スワイプ帯の光る演出、進行バー、時計

**アプリ本来のものを使うもの**
- 各アプリのアイコン

## 10. 実験（実装前・実装初期に確認）

各実験は「合格条件」と「不合格時の対応」をセットで扱う。

### 10.1 家で確認（scrcpy）
| # | 内容 | 合格条件 | 不合格時 |
|---|---|---|---|
| ① | 自作アプリから2アプリを分割で開けるか | `LAUNCH_ADJACENT` で multi-window になる | 分割機能を外し、全画面セットのみに縮小（ユーザーに再相談） |
| ② | PanelActivity を分割の右側に置けるか | パネルが multi-window で表示 | パネル付きセットはホーム画面で代替 |
| ③ | 分割中アプリの上にスワイプ帯を重ねられるか | 帯でスワイプ・長押しを検出、帯以外のタッチはアプリに届く | フローティングボタン方式に変更（再相談） |
| ④ | Apple Music の再生情報と操作 | 曲名・アーティスト・ジャケット・位置・操作が取れる。☆の有無を記録 | 取れない項目は非表示 |
| ⑤ | セット切り替え（分割→分割、分割→パネル、分割→ホーム） | 前のセットが残らず、目的のセットになる | 切り替え手順（ホーム経由など）を調整 |
| ⑥ | 左右の指定 | 指定どおりの左右で開く | 開いたあと入れ替える手段を調査。無理なら左右の入れ替わりを許容 |
| ⑦ | ナビの方式と戻るジェスチャーの競合 | `settings get secure navigation_mode` が 3ボタン、または帯と競合しない | 帯の位置・判定を調整 |

### 10.2 納車後に車で確認（2026-11-21 以降）
| # | 内容 | 合格条件 | 不合格時 |
|---|---|---|---|
| ⑧ | 車ボタン（純正画面に戻る）の仕組み | 純正ランチャーのボタン押下時のログから呼び出し方を特定できる | 車ボタンを非表示 |
| ⑨ | 車からのタッチ | 帯のスワイプ・長押しが車の画面で効く。マルチタッチの可否を記録 | 帯幅を設定で太くする |
| ⑩ | 車接続時の解像度 | どの解像度でもレイアウトが崩れない | レイアウト修正 |
| ⑪ | 純正アプリとの競合 | CarPlay接続時に自作ランチャーが出る（Launcher3 が名指しで起動されない） | 対処を調査（再相談） |

## 11. ビルド・配布

- **リリース用署名鍵を1つ作成し、Claude Code と Antigravity で共有**（別鍵だと上書きインストールできず設定が消えるため）。鍵はリポジトリ外で保管
- インストール：`adb -s 192.168.137.248:5555 install -r app-release.apk`
- 初回セットアップ（adb で一括）：既定のホーム設定、通知アクセス許可（`cmd notification allow_listener`）、オーバーレイ許可（`appops set <pkg> SYSTEM_ALERT_WINDOW allow`）。既定のブラウザは端末の設定画面で選択
- `<queries>` に MAIN/LAUNCHER と http VIEW を宣言（パッケージ可視性）
