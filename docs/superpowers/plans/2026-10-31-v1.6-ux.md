# v1.6 UX 改善(段階 A・B)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **このプロジェクトでは**: 各 Task は指示書 `tasks/NNN-xxx.md`(+ `.allow`)にして `codex-run` で codex に任せ、司令塔(Claude)が `codex-ask` での点検 → 差分レビュー → `codex-verify` → コミットを行う。ブランチは `v1.6`。

**Goal:** v1.6 設計書の段階 A(A1〜A5)と段階 B(B1〜B6)を実装し、迷わず戻れる・失敗が分かる・待ち受けが空っぽに見えない状態にする。

**Architecture:** 既存の画面部品の中で完結する小さな変更が中心。新しく作るのは、失敗を知らせる重ね表示の通知帯(`NoticeOverlay`)と、ドックの `SetAddIcon` だけ。通知は `Messenger` の口を原因別に増やして SetRunner・LinkEntryActivity から呼ぶ。

**Tech Stack:** Kotlin、Jetpack Compose(BOM 2025.01.00)、Robolectric、bash の場面テスト。

**Spec:** `docs/superpowers/specs/2026-10-31-v1.6-ux-design.md`

## Global Constraints
- ブランチ `v1.6`。ビルド・テストは `/home/munde/tools/gradle-run.sh`、`--tests` は引用符で囲む。codex は adb を実行しない。
- タッチ領域 72dp(`Dims.MinTouch`)、本文 20sp 以上(`Dims.BodyText`)、走行中も動作を変えない、幕の安全タイマー 4 秒(延長しない)。
- 文言: 通知・説明は敬体、ボタンは短い動詞。呼び名は「画面セット」/「セット」、「ドック」。
- ドックに文字のラベルを付けない。流れる曲名(3秒待って1周)は変えない。
- テストを弱めない。文言・形の変更に由来する既存の期待値だけ合わせ、どれを変えたか報告させる。
- 段階 C(見た目の整理・緑→白)はこの計画に含めない(モックで選んでから別に足す)。

## Review Focus
1. **通知帯の重なり**: 通知帯(B2)が帯・幕・ドックのボタンの上に重なって押せなくしない(画面の下の中央、両端の帯の内側、幕が出ている間は幕の上に出さない)。→ Task 092 のテスト。
2. **幕の「ホームへ戻る」の後に分割が遅れて出る**: 取り消した後に E の分割が出ても、ホームが前に戻る。次のセットを開く操作を妨げない。→ Task 093 のテスト。
3. **一時停止中のセッションの選び方**: 停止(STOPPED)や、曲名の無いセッションを曲として出さない。複数あれば最近更新されたもの。→ Task 095 のテスト。
4. **ホームの案内の回数**: 案内(A5)は5回を超えたら出ない。設定の「デフォルトに戻す」で回数も戻るかは「戻さない」。→ Task 090 のテスト。
5. **許可の文言の出し分け**: 足りない許可が0件のときは帯を出さない、1件なら理由、2件以上なら件数。→ Task 088 のテスト。
