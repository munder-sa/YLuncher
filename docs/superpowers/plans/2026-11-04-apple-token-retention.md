# Apple接続保持・組み込みログインの実装順序

対応設計: [Apple接続保持設計](../specs/2026-11-04-apple-token-retention-design.md)。2026-11-04、ユーザーの「ok」で実装開始。Task 182〜187で保存/復元/組み込みログインと対象テスト・レビューを完了。追加承認を受けたTask 188/189で通信診断とFast Fallbackを実装し、対象29件/18件のテストとreleaseビルドに成功。本体/中継とも2.3.0-beta6 / 46を実機へ更新済み。

実機では組み込みログイン→暗号化保存、プロセス再作成/同署名上書き後の復元、通信失敗時の保持、接続解除(Webログイン削除OFF)と再取得を確認済み。beta6初回復元2,628ms、解除後の再取得1,941ms。利用者がADBを再有効化した後、端末全体の再起動完了(boot_completed=1/uptime148.44秒)と新PID4412でも、再入力/Webログインなしで2,635msのjp/SAVED復元を確認。WebViews0。認証済みWebデータ削除ON、Apple実TTML2曲/ホーム/パネル/停止/シーク、原因未特定の設定黒画面は未完了。[共有引き継ぎ](../../HANDOFF.md)に現在の状態と次の一手を記録する。以下は当初の工程と検証範囲。

## 工程1: 暗号化保存

- 新規の資格情報ストアとKeystore/AES-GCM実装を分離。noBackupFilesDirと原子的書込み、厳密なサイズ/形式、固定理由での失敗、明示削除を実装する。
- 合成トークンの保存/復号/改ざん/鍵不在/並行更新/削除を対象テストで検証。通常configへ混ぜない。
- ここではWebViewや取得UIを追加しない。既存メモリSessionへの組込みは次工程。

## 工程2: Sessionと復元

- AppGraph/Sessionの初期化と保存担当を接続。認証成功後に保存、必要時の復元/再確認、通信失敗時の保持、認証拒否時の無効化、世代/キャンセル/保存削除競合を実装する。
- 既存の手動入力から保存・再起動復元まで通せる状態にする。未完了の保存を保存済みと表示しない。
- 対象はSession/Repository/Cacheの関連ケースに限定し、既存の優先順位や秘密値非混入の検証を残す。

## 工程3: 組み込みWeb取得

- 提供ZIPのMainActivity/TokenLogicを参照して、非exportedのログインActivity、Cookie/期限/URL境界の純計算を追加。ビルドスクリプトは取り込まない。
- 設定のログイン導線と接続ボタン、手動入力、解除の選択、WebViewログイン領域のbackup除外を追加。WebViewは画面利用時のみ作成する。
- 新依存はWebKitの必要箇所を確定してallowへ明記。ソース/ライセンス記録を残す。既存Music Tokenのインストール/消去/再署名はしない。
- 元の純粋ケースを維持して拡張し、画面中断/戻る/再作成/SSL/外部遷移/非対応端末/未配信結果の秘密値非混入を検証。

## 工程4: ベータ・実機

- 3工程の差分と対象テストを照合してから、本体/中継の次ベータを揃えてビルドする。現在の基準は2.3.0-beta2 / 42。確認済みテストを各工程の後に理由なく繰り返さない。
- 署名/版/HOME/権限を照合して更新。利用者がAppleへログインし、トークン本文はチャット/ADB/証跡へ出さない。
- プロセス再作成、上書き更新、端末再起動、通信不能、解除/再取得を場面ごとに記録する。
- Apple歌詞の実TTML採用・Lemonと別曲・ホーム/パネル・停止/シーク/曲変更も確認する。以前のTask 179未完了をここへ引き継ぐ。
- 失敗例と復旧手順、ユーザーの操作感を記録し、正式版昇格/公開は別途の対象承認に従う。

## 着手前に実装指示書へ具体化する点

- ストアのファイル形式/上限/鍵alias/原子的削除、復元要求の起動条件、保存状態のUI表現。
- WebViewの保存領域とバックアップ除外の対応、Cookie削除完了の扱い。既存ランチャー設定のバックアップは一律に止めない。
- 旧「再入力が必要」の文言に依存するテストの新仕様への移行範囲。その他のセキュリティ/ライフサイクル条件は維持する。
- ビルド時のWebKit依存整合と最小限の導入、実機Keystoreの成立、各工程の具体的な変更対象/テストクラス。
