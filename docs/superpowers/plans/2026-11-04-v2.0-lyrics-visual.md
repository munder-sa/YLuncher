# v2.0.0 歌詞と背景の見た目 Implementation Plan

> このプロジェクトでは、司令塔(Claude)が各 Task を `tasks/NNN-xxx.md` と `.allow` にし、codex-run で実装を依頼する。司令塔が点検・差分レビュー・検証・コミットを担当する。この計画自体はコマンド実行や変更ファイルの許可ではない。Task 149 ではこの計画と設計書だけを作る。

**Goal:** GT8D の描画上限を踏まえ、ホームのミニプレイヤーに暗い静止背景と読みやすい現在行・次行を加え、可視行の短い時間差と控えめな縮小を実装する。

**Architecture:** Bitmap の縮小・ヒストグラム・暗色化を UI から分離し、ホームの状態保持部品が画像変更時だけワーカーで計算する。背景はキャッシュした Brush。歌詞の可視判定・遅延計画を純粋な関数にし、行の安定キーごとの層の状態で表示位置を保持する。色・縮小・時間は `LyricsVisualStyle` に集約する。

**Tech Stack:** 既存 Kotlin、Jetpack Compose、Android Bitmap、coroutines、JUnit、coroutines-test、Robolectric。依存関係の追加なし。

**Spec:** `docs/superpowers/specs/2026-11-04-v2.0-lyrics-visual-design.md`。基準は `2026-11-03-lyrics-design.md` の r1.4・r1.5 と現行 v1.7.1。調査 `tasks/149-research-amll.md.txt` は考え方の参考のみ。

## Global Constraints

- ブランチ `v2.0`。ブランチ操作、gitコミット/リセット、main取り込み、タグ、リリースは司令塔。codex は行わない。
- GT8D の GPU 側は全画面約50ms/フレーム(既存実測)。背景は静止。常時更新、ぼかし、動くメッシュを足さない。
- Task 142〜145 の層による動作を維持する。アニメーション値は `graphicsLayer`・`placeRelativeWithLayer` の層ブロックで読み、毎フレームの組立て直し・再計測・再配置を起こさない。
- リリース版の画面全体を「パネル」1つとするユーザー補助の構造を維持。行別 semantics はテスト時だけ。BuildConfig を有効にしない。
- 新規ライブラリなし。AMLL/AMLL-DroidMate のコードやシェーダーをコピーしない。TTML DB は別調査。
- 歌詞22sp・行間16dp・送り800ms・明るさ500ms・単語時刻がある場合だけ塗る仕様を維持。タッチ72dp・本文20sp以上。取得・設定・キャッシュ・既存マーキーを変えない。
- 画像処理はメインスレッド外。元 Bitmap を破棄/変更しない。キャンセルを握りつぶさない。
- ビルド・テストは `/home/munde/tools/gradle-run.sh` 経由。`--tests` は必ず `:app:testDebugUnitTest --tests '...'`。Gradle は同時に最大2本、同一作業ディレクトリのビルドは直列。並列実装は司令塔が分離した作業場所と許可を用意した場合のみ。
- テストは触ったパッケージだけ。全テストはベータ実機確認後に最後の1回。codex は adb を実行しない。
- beta は `2.0.0-betaN`、正式版は `2.0.0`。versionCode は毎回直前の配布より増やす。現行ファイルは30/1.7.1だが、配布台帳を確認して決め、固定で31とはしない。
- 既存テストを削除・無効化・緩和しない。仕様と旧期待値が衝突する場合は RULES.md の3点セットで止まり、司令塔が仕様に基づく対応を指示書へ明記する。
